# WorkBench 开发工作流

## 启动开发服务器

```bash
cd D:\workspace\workspace_ai\demo_OpenSpec\git_tools\workbench
wails dev
```

## Linux 本地开发环境（WSL2 / 原生）

安装 Wails 桌面编译依赖（Ubuntu 22.04+ / Debian 12+）：

```bash
sudo apt-get update
sudo apt-get install -y build-essential pkg-config libgtk-3-dev libwebkit2gtk-4.1-dev
```

安装 Wails CLI 与前端依赖后照常 `wails dev` / `wails build`；Linux 构建须叠加 webkit 标签（仓库仅提供 webkit2gtk-4.1）：

```bash
wails build -tags webkit2_41
```

环境自检用 `wails doctor`。注意点：

- 依赖安装边界（判定以 [linux-platform.md §3](spec/linux-platform.md) 为单一事实源）：后端四子包测试（`go test ./model/ ./service/ ./util/ ./server/`）与 `go build ./...` / `go test ./...`（主包不带 desktop,production 标签，不触 Wails 桌面前端 CGO）均**无需**安装 GTK/WebKit 依赖；仅 `wails build` / `wails dev`（等效 desktop,production 标签，桌面前端 CGO 进编译图）需要上述依赖，且须叠加 `webkit2_41` 标签（详见上节）。浏览器访问模式（`--serve`）为运行态，无 GTK 依赖
- 桌面窗口经 WSLg 运行（需 Win11 或已装 WSLg 的 Win10）
- 项目位于 `/mnt/d/...`（Windows 盘挂载）时 Go/npm I/O 性能明显偏低，频繁全量构建建议将仓库放入 Linux 文件系统

## 运行测试

```bash
# 后端测试
go test ./...

# 前端测试
cd frontend
npm test

# 查看测试覆盖率
npm run test:coverage
```

## 构建生产版本

```bash
wails build -clean
# 输出：build/bin/workbench.exe (13MB)
```

## 运行应用

```bash
# 开发模式
wails dev

# 生产模式
build\bin\workbench.exe
```
