# WorkBench 测试策略

## 单元测试

- **后端：** 测试模型验证、服务逻辑、Git 操作、文件 IO、AI 功能归档（约 170 个测试用例）
- **前端：** 测试组件行为、用户交互、边界情况、Pinia store、composable 纯逻辑（约 380 个测试用例）

## 集成测试

- **前后端绑定：** 测试Wails方法调用
- **文件操作：** 测试真实文件系统操作
- **Git集成：** 测试Git命令执行

## 测试覆盖

- 根节点检测逻辑
- 节点切换时预览清理
- 错误处理运算符优先级
- Debug工具功能
- 后端文件操作（创建/重命名/删除/OpenInExplorer）
- 后端Git扫描与批量拉取（ScanGitRepos/BatchPull）
- 前端右键菜单分发、重命名、删除、复制、资源管理器打开

## 覆盖率门禁

### 后端

`scripts/coverage-check.sh` 解析 `go test ./... -coverprofile` 各包覆盖率，按分层阈值校验，超阈值 `exit 1`。

| 包 | 阈值 | 说明 |
|---|---|---|
| model | ≥ 80% | 纯逻辑/校验，已达标 |
| server | ≥ 80% | 预览 HTTP handler，已达标 |
| service | ≥ 76% | 业务密集，含 RunStage/pumpOutput/pty/网络下载等系统调用核心无法单测，实际可达上限约 76% |
| util | ≥ 40% | 排除 pty_windows.go 系统调用文件后计算 |
| workbench 主包 | 不设门禁 | app_*.go 为转发 service 的薄包装，service 已测则重复验证价值低 |

运行：`bash scripts/coverage-check.sh`

### 前端

`vitest.config.js` 配置 `coverage.provider: 'v8'` + `thresholds`（lines/branches/functions/statements 全 ≥70%，硬失败）。`npm run test:coverage` 低于阈值 `exit` 非 0。

已达标基线（statements 78.84 / branches 70.26 / functions 73.75 / lines 81.67），36 个 spec 共 715 用例。coverage 配置 `exclude: ['wailsjs/**']` 排除 Wails 运行时生成绑定（`wailsjs/go`、`wailsjs/runtime` 非业务代码，原 0% 覆盖率不再拖低整体）。交互组件依赖 Wails 绑定与 Element Plus stub，composables/useTerminal（pty 系统调用）本征难测保持低位，由其余组件测试拉齐整体到 70%。

运行：`cd frontend && npm run test:coverage`
