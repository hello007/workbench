# WorkBench 测试策略

## 单元测试

- **后端：** 测试模型验证、服务逻辑、Git 操作、文件 IO、AI 功能归档（约 170 个测试用例）
- **前端：** 测试组件行为、用户交互、边界情况、Pinia store、composable 纯逻辑（约 380 个测试用例）

## 集成测试

- **Git 关键流程（后端层）：** `git_flows_integration_test.go`（构建标签 `integration`），`t.TempDir()` 构造真实 git 仓库 + 本地 bare 远程 fixture，经 `AppServices` 组装真实 service 链（无 mock）驱动提交/推送/分支/合并/变基/冲突解决全链路；运行 `go test -tags=integration ./...`（默认 `go test ./...` 不编译，覆盖率门禁不受影响）
- **前后端绑定：** 测试Wails方法调用
- **文件操作：** 测试真实文件系统操作
- **Git集成：** 测试Git命令执行

## E2E 测试（方案 C 混合架构）

WorkBench 是 Wails v2 桌面应用，无官方 E2E 支持；Playwright 驱动真实 WebView2（CDP 注入）CI 成本高且 flaky，故采用混合方案——前端 E2E 测 UI 编排、后端集成测试测业务链路，两侧各自稳定、CI 并行：

| 层 | 载体 | 覆盖 |
|---|---|---|
| 前端 E2E | Playwright + `vite preview` web 版，`window.go` / `window.runtime` 全 mock | Git 提交/推送、分支管理、合并/变基三个关键流程的 UI 编排与跨组件操作链 |
| 后端集成测试 | `go test -tags=integration`（见上节） | 同三流程的真实 git 业务链路 |

### 运行方式

```bash
cd frontend
npm run e2e:install   # 首次：安装 Chromium（仅首次或升级版本后）
npm run e2e           # webServer 自动 vite build + vite preview（固定端口 4173）
npm run e2e:report    # 查看最近一次 HTML 报告（含失败 trace）
```

本地 `retries=0`；CI 环境（`CI=true`）自动 `retries=2` + `forbidOnly` + github/html reporter。

### 目录职责与用例约定

见 [frontend/e2e/README.md](../frontend/e2e/README.md)。要点：

- 用例从 `e2e/fixtures.js` import `{ test, expect }`（自动注入 Wails mock，禁直接 import `@playwright/test`）
- mock 默认返回值单一数据源 `src/test/wails-mock-defaults.js`（vitest setup 与 E2E 共用基础表，行为不漂移）
- 调用链断言用 `getWailsCalls(page, method)`；禁 `waitForTimeout`，靠 expect 自动重试（见 [spec/test-stability.md](spec/test-stability.md)）
- E2E 规范详见 [spec/e2e-testing.md](spec/e2e-testing.md)（mock 约束、构建标签隔离、CI 绑定生成要求）

### CI 集成

`.github/workflows/ci.yml`（push master / pull_request 触发，ubuntu-latest）：Go 单测 → Go 集成测试 → 前端构建 → Playwright E2E → 前端单测，失败时上传 E2E 报告 artifact（保留 7 天）。`frontend/wailsjs/` 不入库，CI 在测试前经 `wails generate module` 重新生成绑定。与 `release.yml`（tag 触发发版，Windows runner）互不冲突。

## 覆盖率门禁

### 后端

`scripts/coverage-check.sh` 解析 `go test ./... -coverprofile` 各包覆盖率，按分层阈值校验，超阈值 `exit 1`。

| 包 | 阈值 | 说明 |
|---|---|---|
| model | ≥ 80% | 纯逻辑/校验，已达标 |
| server | ≥ 80% | 预览 HTTP handler，已达标 |
| service | ≥ 76% | 业务密集，含 RunStage/pumpOutput/pty/网络下载等系统调用核心无法单测，实际可达上限约 76% |
| util | ≥ 40% | 排除 pty_windows.go 系统调用文件后计算 |
| workbench 主包 | 不设门禁 | app_*.go 为转发 service 的薄包装，service 已测则重复验证价值低 |

运行：`bash scripts/coverage-check.sh`

### 前端

`vitest.config.js` 配置 `coverage.provider: 'v8'` + `thresholds`（lines/branches/functions/statements 全 ≥70%，硬失败）。`npm run test:coverage` 低于阈值 `exit` 非 0。

已达标基线（statements 78.84 / branches 70.26 / functions 73.75 / lines 81.67），36 个 spec 共 715 用例。coverage 配置 `exclude: ['wailsjs/**']` 排除 Wails 运行时生成绑定（`wailsjs/go`、`wailsjs/runtime` 非业务代码，原 0% 覆盖率不再拖低整体）。交互组件依赖 Wails 绑定与 Element Plus stub，composables/useTerminal（pty 系统调用）本征难测保持低位，由其余组件测试拉齐整体到 70%。

运行：`cd frontend && npm run test:coverage`
