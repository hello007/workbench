## 一、摘要

岛仔（Daozai）是基于 Rust + egui 的 Windows 桌面信息岛，常驻屏幕顶部，聚合音乐歌词、邮件验证码、日程、待办、AI 额度与系统状态。

**核心结论：**

1. Dz 与 WorkBench 场景不同（消费级信息聚合 vs 开发者工作台），**应借鉴机制，不借鉴场景**。
2. 有 **7 项机制可直接复用**，其中 3 项属于 WorkBench 当前空白：托盘常驻、长任务提醒、AI 额度可视化。
3. 灵动岛界面在 WorkBench 技术栈内**可以实现**，但受 Wails v2 单窗口限制，需以独立子进程形态承载；视觉可还原，仅“背景采样自适应着色”无法复刻。
4. 建议分四批落地，首批约 5 人日，收益最高、风险最低。

## 三、项目概览

### 3.1 功能矩阵

| 功能 | 能力要点 |
|---|---|
| 桌面伙伴 | 待机动画、极简模式 |
| 音乐与歌词 | 读取 Windows 系统媒体会话（SMTC），控制播放、单行歌词 |
| 专注与饮水 | 专注/休息计时、饮水目标与提醒时段 |
| 文件置物架 | 拖入临时收集、打开/定位、拖出到其他应用 |
| 待办 | 增删改、日期时间选择器、可选提醒 |
| 邮件 | 六类邮箱 IMAP、验证码识别与复制、正文阅读 |
| 日程 | 飞书/钉钉/企微 CalDAV 只读、月历、重复日程、单次修改/取消 |
| AI 额度 | Codex、Claude、Kimi、Grok、Gemini，多账号、常驻圆环 |
| 系统提示 | 电量、网络、音量、大写锁定、输入语言、蓝牙设备 |

### 3.2 架构特征

- **平台外壳与界面分离**：`main.rs` 只做 Windows 无边框透明窗口 + 托盘 + 系统数据，界面主体在 `app.rs`，同一份代码被无窗口录制器复用。
- **服务化采集**：邮件、日程、额度各自维护后台线程 + 通道事件（`Service` 结构 + `try_recv`），主线程轮询消费，不阻塞渲染。
- **时间注入**：界面时间统一来自 `Env::t`，不直接读系统时钟，因此录屏可逐帧复现。
- **数据与凭据分离**：配置写入 `%APPDATA%\Daozai`，密码进 Windows 凭据管理器，独立会话用 DPAPI 加密。

## 五、P0 项详述

### 5.1 长任务完成原生提醒

**借鉴机制**

Dz 将提醒分为两类：可打断的主通知与低优先级 HUD；后者进入队列合并展示，同一时段不叠加弹窗（`src/extras.rs` 的 `enqueue_alert`、`tick_alerts`）。

**WorkBench 现状**

无任何通知能力：前端未使用 Web Notification，后端无 toast 调用。

**落地路径**

1. Wails v2.16 已内置原生通知：`runtime.SendNotification`、`SendNotificationWithActions`、`OnNotificationResponse`。Windows 侧使用 `go-toast` 并注册 AppUserModelId（`internal/frontend/desktop/windows/notifications.go`），无需引入第三方通知库。
2. 新增 `service/notification_service.go`，订阅既有事件流：
   - `service/ai_function.go`：任务完成/失败
   - `service/assets_split.go`：批量拆分完成
   - Git 批量拉取、克隆结束
3. 通知动作按钮：“打开任务详情”“忽略”，经 `OnNotificationResponse` 回调前端。
4. 节流规则：同类型任务 30 秒内最多一条；失败必弹、成功可配置；前台窗口聚焦时不弹。

**风险**

系统“勿扰/专注助手”会吞通知，需在设置页说明；发送前须调用一次 `InitializeNotifications`。

### 5.2 AI 额度常驻与任务前预警

**借鉴机制**

Dz 只读本机登录态，调用各厂商用量接口，解析“5 小时窗口 / 本周窗口”的剩余比例与重置时间，多账号分别配色（`src/quota.rs` 的 `Window`、`Snapshot`、`cadence`）。

**关键实现**

- 接口：`https://api.anthropic.com/api/oauth/usage`，请求头附带 `anthropic-beta: oauth-2025-04-20`（`src/quota.rs:246`）。
- 登录态：从 Claude 桌面版加密 tokenCache 只读解析（`src/claude_quota.rs`），明确不回写原客户端配置。
- 容错：窗口字段可能为 `null`，数字可能以字符串返回，解析层做了兼容。

**WorkBench 适配**

WorkBench 通过 `claude -p` 子进程执行 AI 功能，与本机 Claude Code 登录态同源。建议读取 Claude Code 凭据文件中的 OAuth accessToken（具体字段与路径需实测确认，Dz 读的是桌面版配置，两者不同）。

**落地路径**

1. 新增 `service/ai_quota_service.go`，60 秒轮询；失败静默降级，不打扰用户。
2. 事件 `ai-quota:update` 推送前端，用于状态栏圆环与 Home 卡片，展示“5 小时剩余 62%，18:40 重置”。
3. AI 任务启动前若剩余低于 15%，弹确认“额度将耗尽，是否继续”。
4. 多账号按 Claude 配置目录区分并支持命名。

**风险**

接口非公开，随时可能变更，必须有开关与降级；token 过期需引导用户重新登录 Claude Code。

### 5.3 托盘常驻、单实例、开机自启

**借鉴机制**

- 单实例：命名互斥体，重复启动时把参数转发给已运行实例（`src/main.rs` 对 `--settings`、`--calendar` 的处理）。
- 托盘：菜单每次打开实时计算勾选态；系统重启资源管理器后响应 `TaskbarCreated` 重建图标。
- 自启：写 `HKCU\Software\Microsoft\Windows\CurrentVersion\Run`。

**WorkBench 现状**

无托盘，关闭窗口即退出；长时间 AI 任务与批量 Git 操作会被直接中断。

**能力核实**

- Wails v2.16.0 源码中**无** `TrayIcon`/systray API，仅存在 Win32 常量定义；托盘需第三方库（`energye/systray`）或直接 `Shell_NotifyIcon`。
- 单实例**已内置**：`options.App.SingleInstanceLock`，含 `OnSecondInstanceLaunch` 回调，无需自建互斥体。
- 关窗隐藏**已内置**：`options.App.HideWindowOnClose`。

**落地路径**

1. 启用 `SingleInstanceLock`，`OnSecondInstanceLaunch` 中根据参数显示主窗口或打开设置。
2. 托盘做 0.5 天 spike：验证第三方托盘库消息循环与 Wails 主线程不冲突；不通过则退回“关闭最小化到任务栏”加通知。
3. 关闭按钮改为隐藏到托盘，首次提示“已最小化到托盘，右键退出”。
4. 托盘菜单：显示主窗口、AI 任务状态、开机自启、退出。
5. 自启写注册表，状态实时读取而非缓存。

**风险**

托盘库线程模型；Linux 无系统托盘需降级，与现有跨平台策略保持一致。

### 5.4 数据目录可覆盖

**借鉴机制**

Dz 默认 `%APPDATA%\Daozai`，同时支持环境变量 `DAOZAI_DATA_DIR` 覆盖；测试通过单线程执行加独立目录隔离（README 明确说明原因）。

**WorkBench 现状**

`data/` 为相对 exe 的目录，便携性好，但测试会触碰真实数据，且换目录易丢配置。

**落地路径**

1. `util` 增加单点 `DataDir()`：优先环境变量 `WORKBENCH_DATA_DIR`，否则沿用当前相对路径，保持默认行为不变。
2. 测试与 E2E 统一注入该变量，替代手工清理。
3. 可选增强：设置页提供“迁移数据目录”，带备份与回滚。

**价值**

直接对齐项目既有规则“测试禁隐式依赖环境外部状态”。

## 六、P1 项详述

### 6.1 文件拖出到外部应用

**借鉴机制**

`src/system.rs` 使用 COM `IDataObject` + `DoDragDrop`，把文件路径封装为原生拖放数据，浏览器、资源管理器、WPS 均可接收。

**WorkBench 价值**

素材面板把 PPT 拖到 WPS/资源管理器属高频动作，当前仅支持“打开/定位”。Wails 只提供 `OnFileDrop`（入向），出向需自行实现。

**分级方案**

| 方案 | 成本 | 覆盖场景 |
|---|---|---|
| 右键“在资源管理器中显示”“复制路径” | 0.5 人日 | 约 80% |
| Win32 COM 完整拖出 | 3 人日 | 全部，需处理 OLE 初始化与消息循环 |

### 6.2 槽位布局与弹簧动画

**借鉴机制**

`src/bar_layout.rs` 维护固定槽位宽度表与每槽弹簧位置，组件显隐时平滑重排并保证不重叠，配套“任意组合不重叠”单测。

**WorkBench 适配**

顶部状态栏 chip（分支、同步态、AI 任务、素材扫描）动态出现会导致跳动。可移植为 Vue composable：槽位宽度预算 + CSS transition，单测断言不重叠。

### 6.3 玻璃层对比度自适应

**借鉴机制**

`src/glass.rs` 以二分法求最小着色量，使文字与背景对比度不低于 WCAG 4.8；背景越亮，着色越深。

**WorkBench 适配**

命令面板、预览遮罩、AI 对话浮层可借此保证可读性。实现为 CSS 变量 + 前端工具函数即可，无需 GPU 着色器。落地时须并入现有 `design-tokens` 规范，避免新增割裂色阶。

### 6.4 专注模式

**借鉴机制**

专注/休息分段计时、独立顶部条、到点提醒；饮水与提醒时段可配置。

**WorkBench 适配**

只借“专注 + 静默”：专注期间抑制非关键通知、隐藏侧边栏、记录时长；与现有 `StatsView` 的提交与编辑统计联动，形成“专注产出”卡片。饮水、桌面伙伴不借。

### 6.5 日程与会议聚合（P2，按需）

**借鉴机制**

- CalDAV 只读接入：`PROPFIND` 发现日历，`REPORT calendar-query` 查询区间，三家国内办公平台均为 Basic Auth，无需 OAuth。
- 去重：`UID + 开始时间` 组合键。
- 重复日程：支持单次修改、取消、EXDATE。
- 会议邀请：解析邮件 MIME 中的 ICS 部件。

**WorkBench 适配**

仅在需要“迭代/发布日历提醒”时实施。工作量集中在重复日程展开与去重，不建议一期投入。

## 七、专题：灵动岛界面的可行性

### 7.1 结论分层

| 目标 | 可行性 | 手段 |
|---|---|---|
| 视觉：圆角悬浮条、展开/收起、动效、毛玻璃 | 可行 | Wails 窗口选项 + CSS，无需原生代码 |
| 交互：不抢焦点、透明区域点击穿透、悬停展开 | 可行但需 Win32 补丁 | WndProc 子类化 + `SetWindowRgn` |
| 形态：与主工作台窗口并存 | 单进程做不到 | 第二个进程，或升级 Wails v3 |

### 7.2 Wails v2.16.0 能力核实

| 能力 | API | 结论 |
|---|---|---|
| 无边框 | `options.App.Frameless` | 有 |
| 置顶 | `AlwaysOnTop` / `runtime.WindowSetAlwaysOnTop` | 有 |
| 透明背景 | `windows.Options.WebviewIsTransparent` + `BackgroundColour` alpha 0 | 有 |
| 窗口半透明 | `Windows.WindowIsTranslucent` | 有 |
| 云母/亚克力 | `Windows.BackdropType` | 仅 Win11 22621+ |
| 启动隐藏 / 关窗隐藏 | `StartHidden` / `HideWindowOnClose` | 有 |
| 单实例 | `options.App.SingleInstanceLock` | 有内置 |
| 尺寸与位置 | `WindowSetSize` / `WindowSetPosition` | 有，原生重排有成本 |
| 多显示器 | `runtime.ScreenGetAll` | 有 |
| 托盘 | 无 | v2.16 无 TrayIcon API |
| 多窗口 | 无 | 运行时仅当前窗口 |
| 取窗口句柄 | 无 | 需 `FindWindow`/`EnumWindows` 自取 |

### 7.3 三条技术路线

**路线 A：小窗口 + CSS 动画（推荐 MVP）**

岛为独立小窗口，仅覆盖可见区域；收起 180×40、展开 520×220，用 `WindowSetSize` 切换，内部元素用 CSS 变形。

- 成本：3 人日
- 优点：不碰 Win32，点击穿透问题天然不存在
- 缺点：尺寸切换有原生重排，可能 1 帧抖动；`ResizeDebounceMS` 可缓解
- 适用：AI 任务进度条、Git 操作状态条

**路线 B：大窗口 + `SetWindowRgn` + WndProc 子类化（最接近原版）**

覆盖屏幕顶部的大透明窗口，用 `SetWindowRgn` 裁出岛形状；子类化窗口过程，在岛外返回 `HTTRANSPARENT`。基本是 `src/native.rs` 的逐行翻译。

- 成本：6 人日
- 关键点：
  - 使用 `SetWindowRgn`，**不要** `WS_EX_LAYERED` 整窗透明，WebView2 下易黑屏或闪烁
  - `WS_EX_NOACTIVATE` 抑制激活，避免点击岛时抢走编辑器焦点
  - 展开时 `SetWindowPos(HWND_TOPMOST, SWP_NOACTIVATE)` 维持置顶
- 优点：形变连续、可点击穿透、视觉最接近
- 缺点：WebView2 在裁剪窗口上的合成稳定性需实测；代码集中在平台层，可沿用 `_windows/_other` 双文件约定

**路线 C：升级 Wails v3 或更换技术栈**

v3 具备原生多窗口与托盘，但迁移面覆盖全部绑定层，不建议为单一界面升级。

### 7.4 架构约束：主窗口不能同时是岛

Wails v2 单窗口，岛与工作台二选一。可行方案为**同二进制双进程**：

1. 打包为一个 exe，`--island` 参数启动岛进程，`SingleInstanceLock` 仅在工作台模式启用。
2. 两进程通信复用现有浏览器通道 RPC 与事件流，token 认证现成，无需新建 IPC。
3. 岛进程只做展示与轻交互，业务逻辑仍留主进程，避免状态双份。
4. 主进程退出时通知岛进程退出；岛进程崩溃不影响主进程。

### 7.5 视觉还原度边界

| Dz 效果 | WebView2 还原度 |
|---|---|
| 圆角与阴影 | 完全还原 |
| 展开弹簧动画 | 接近，DOM 动画更细腻 |
| 背景采样自适应着色（`src/glass.rs`） | **无法复刻**，`backdrop-filter` 只采样页面内容，采不到桌面 |
| 毛玻璃质感 | 近似：`BackdropType=Acrylic`（Win11），Win10 降级为半透明纯色 |
| 逐像素命中测试 | 可还原，需路线 B 的子类化 |
| 前台全屏时自动隐藏 | 需 Win32 查前台窗口矩形，约 0.5 人日 |

**结论：除“背景采样自适应着色”外均可还原**；玻璃质感用“亚克力 + 预设三档 tint”替代。

## 八、工程方法借鉴

| 方法 | Dz 做法 | 适用性 |

| 外部登录只读 | 明确不回写原客户端配置，登录文件只读解析 | 可直接写入 AI 相关规范 |

| 邮件 IMAP 与验证码提取 | WorkBench 无邮件场景；“加权打分 + 负向词表 + 宁可漏不可错”的思路可另用于日志脱敏，但需单独评估 |

## 十二、总结

1. **优先级明确**：托盘常驻、长任务提醒、AI 额度三项填补 WorkBench 空白，投入产出比最高。
2. **技术边界清晰**：Wails v2.16 已内置单实例与原生通知，但无托盘与多窗口；灵动岛需独立进程承载，交互细节需 Win32 补丁。
3. **避免误投入**：邮件、媒体、桌宠等场景不迁移；背景采样着色不可复刻，不应作为验收标准。
4. **待验证项**：第三方托盘库与 Wails 线程模型兼容性、Claude Code 凭据文件字段、WebView2 裁剪窗口合成稳定性。
