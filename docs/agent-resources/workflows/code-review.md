# Code Review 工作流

适用于对代码变更做质量审查的任务。

## 核心原则

- 对代码不对人——评审的是代码，不是写代码的人
- 发现问题要有具体的文件、行号、原因
- 按严重程度分级，不把风格问题和正确性问题混为一谈
- 不只挑问题，好的地方也可以指出
- 不执行 git commit / git push（除非用户明确要求）

## 评审维度

### 1. 正确性（最高优先级）

- 业务与计算逻辑是否正确，是否存在潜在边界错误（空值、未定义、数组越界、goroutine 泄漏）。
- Vue 响应性机制：是否意外解构响应式对象导致响应性丢失，是否使用 `toRefs` 保持响应性。
- 计算属性与监听：`computed` 必须是只读纯函数（严禁产生副作用或异步操作）；`watch` 是否必要，深层监听是否有性能损耗。
- 实例代理：复杂第三方对象（ECharts、CodeMirror、xterm 实例）是否使用 `shallowRef` / `markRaw`，严禁深层代理。
- 异常与错误处理：是否吞掉异常或未做 Promise catch 兜底；Go 侧是否用 `log/slog`（禁 `println`）、错误是否 `%w` 包装保留链条。
- 资源销毁：组件卸载或 repoPath 切换时，定时器、`EventsOn` 监听闭包、终端/编辑器实例是否正确注销。

### 2. 契约与兼容性

- 跨层契约：App 方法签名、`model/` struct 字段变更是否同步前端消费面。
- 组件契约：Props、Emits、Slots 命名是否保持兼容，是否有破坏性变动。
- 配置兼容：配置 key、错误码、settings 段是否向后兼容（新增设置段走双单点，细节见仓根 AGENTS.md 关键规则）。

### 3. 安全性

- XSS 防御：使用 `v-html` 或富文本/mermaid 渲染时是否有安全过滤。
- 敏感信息：代码严禁硬编码密钥、Token、密码；内网地址与凭据不得写入待推仓库。
- 依赖安全：新依赖是否已登记 `check-dep-consistency.mjs` 分档清单、是否引入高风险包。

### 4. 性能影响

- 重复计算与重渲染：是否存在不必要的大量组件重渲染、重复 git 子进程调用。
- 列表与树：大列表是否有截断/虚拟化考量（参照本仓 2000 节点截断惯例）。
- 缓存：聚合缓存是否按既定入口联动失效（两入口联动清除）。

### 5. 可维护性与规范

- 命名规范：遵循项目既有命名风格，清晰表意。
- 架构分层：是否遵守分层与依赖方向，严禁底层反向依赖上层（存量例外以白名单记录为准）。
- 注释与文档：新增机制是否需要沉淀 `docs/spec/` 或 AGENTS.md 关键规则。

### 6. 可测试性

- 核心业务逻辑是否与 UI / 桥接层充分解耦，便于单独编写单元测试。
- 测试是否遵守稳定性约定（无 mtime 时序依赖、无固定端口、无 sleep）。

## 工作流程

### 第一步：获取变更范围

明确评审范围：
- 是暂存区变更？还是某个分支？还是指定文件？
- 涉及哪些模块（Go 后端包 / 前端哪一层）
- 改动量大概多大

使用以下方式获取 diff：
- `git diff` / `git diff --cached`
- 或者直接读取指定文件

### 第二步：通读改动

先整体过一遍改动，理解：
- 改动的目的是什么
- 整体思路对不对
- 有没有遗漏的相关文件（配置、注册、wailsjs 同步、文档）

### 第三步：逐维度审查

按上面的评审维度，从高优先级到低优先级逐一检查。

**常用工具：**
- CodeGraph 分析调用链和影响范围
- 搜索相关用法确认一致性
- 查看历史变更理解上下文

### 第四步：分级输出结果

每个发现都按以下格式输出：

```
[严重级别] 文件:行号 — 简述
  原因：为什么是问题
  建议：怎么改（可选，简单问题可以不给建议）
```

**严重级别定义：**

| 级别 | 含义 | 例子 |
|------|------|------|
| 严重 | 必须改，会导致 Bug 或安全问题 | 响应性丢失、监听未注销导致泄漏、跨层契约破坏 |
| 建议 | 应该改，影响质量但不紧急 | 命名不规范、缺少必要单元测试、缓存未联动失效 |
| 风格 | 可选改，纯偏好类 | 代码格式、写法选择、注释详略 |

### 第五步：总结

最后给出整体评价：
- 改动是否可以通过
- 有几个严重问题、几个建议
- 有没有需要特别关注的风险点

## 不做的事

- 不直接修改被评审的代码（除非用户明确要求修复）
- 不在评审里引入和本次改动无关的问题
- 不因为个人偏好纠结风格问题
