# 临时会话记忆：待办与欠账

> agent 在会话中记下的**待办事项清单**，属临时会话记忆（`temp-memory/`）——每条都有出口，人处理完即删，不长期停留。
> 只记跨会话、对所有人都成立的欠账与待判断项。
> **不要写个人 session 的内容**——「我在做什么」「本次改了哪些文件」「哪些还没提交」属于个人上下文，写进 auto memory 或提交说明，不要写这里。
> **积压提醒**：待办 + 欠账合计超过 10 条时，agent 须在回复中提醒用户处理，不自行处置。

## 更新时机

**立即更新**的情况（agent 遇到以下场景必须主动更新本文件）：

1. **发现跨会话欠账**：用户提到或你发现任何"还未完善"、"待补充"、"暂不可用"、"尚未启用"、"缺失"的项目组成部分
2. **待决事项有了结论**：之前记录的"需要人判断"或"杂项欠账"有了明确答案或决策
3. **发现架构/设计不一致**：文档与代码不符、规范与实际有偏差、配置缺失但功能声称支持等
4. **发现跨会话阻塞项**：任何会影响后续会话、需要人工介入或团队决策的问题

**不写入本文件**的内容：
- 个人 session 的进度（"我在做什么"、"本次改了哪些文件"）→ 写入个人 auto memory
- 已解决的问题 → 直接删除，不留历史
- 单次会话内能解决的临时疑问 → 当场澄清即可

**触发关键词示例**：未完善、待补充、暂不引用、尚未启用、缺失、待定、需要确认、不一致、待人判断、跨会话、阻塞

**积压检查**：追加条目后数一下「需要人判断的」+「杂项欠账」合计条数，**超过 10 条**就在本次回复里提醒用户处理，并说明当前条数——agent 不自行处置这些条目。
