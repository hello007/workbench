# WorkBench 功能说明

## 1. 工作目录管理

- 添加/删除/更新工作目录
- 设置默认目录
- 拖拽排序目录顺序
- JSON持久化配置
- 路径验证（Windows格式）
- 右键菜单：重命名（F2）、设为默认、复制路径、在资源管理器中打开、用 VSCode 打开、用 Warp 打开、用 Obsidian 打开（以该目录作为 Obsidian 仓库）、更新仓库、跳转仓库统计（仅 git 仓库工作目录显示，一键设为当前选中仓库并切到统计面板）、删除（Delete）
- Git 仓库标记：本身是 git 仓库的工作目录项显示 git 图标；已配置远程显示彩色 git.png，未配置远程显示灰色 git-gray.png，便于一眼识别
- 仓库列表配置导入导出：工作目录面板工具栏「导出/导入」按钮
  - 导出：后端将工作目录（名称/路径/默认标记）+ 收藏夹（路径/别名/分组/收藏时间）组装为带 `manifestVersion` 的 JSON（v1），前端经原生保存对话框选路径落盘；运行时态（git 标记/远程标记）与本机标识（目录 ID/创建时间）不导出
  - 导入：选 JSON → 后端解析生成预览（新增/冲突/非法三类，不落盘）→ 冲突项（路径已存在）逐项决策「跳过/覆盖本机/另存为新项」（默认跳过）→ 确认后合并落盘（保留本机已有项，merge 语义）→ 结果汇总（新增/覆盖/跳过/失败计数）
  - 容错：非法 JSON 或 `manifestVersion` 高于当前支持时整体拒绝并结构化报错（`E_REPO_CONFIG_INVALID_JSON` / `E_REPO_CONFIG_UNSUPPORTED_VERSION`）；逐项路径为空或路径在本机不存在列入非法项（带原因），不阻断合法项导入；收藏夹导入后超 100 条上限的部分计入失败
  - 另存为新项语义：本机条目保留，导入项以新身份并存——工作目录重新生成 ID 且名称追加「（导入）」后缀（默认标记强制取消）；收藏夹同路径可共存（分组/别名不同即有意义）

## 2. 文件树浏览

- 懒加载机制（按需加载子节点）
- Git仓库自动检测（git 图标标识，彩色/灰色区分有无远程）
- .git文件夹过滤
- 全部展开/收起功能
- 节点选择和高亮
- 点击祖先目录时仅选中不收起（向上导航保护）

## 3. 文件操作

- 创建文件/文件夹
- 重命名、删除
- 文件预览（支持文本/二进制检测）
- unsupported 按文本预览 - 无扩展名或未知扩展名文件优先尝试按文本读取（UTF-8 优先 + GBK 兜底解码），可显示则降级为文本预览；含 NUL 字节或解码失败的二进制文件、超大文件（>1MB）走降级提示
- 文件预览编辑 — 预览文本文件时可就地编辑，修改后保存或取消，切换文件时自动检查未保存修改；编辑态支持 Ctrl+S 保存、Esc 取消（有未保存修改时二次确认）；保存按原文件编码（UTF-8/GBK）写入，不改变原文件编码（GBK 文件编辑后仍为 GBK）
- Markdown 预览链接导航 — 相对引用（./other.md、../readme.md）在预览面板内切换预览；外部 http 链接用系统浏览器打开；同文档锚点（#标题）滚动定位
- Markdown 预览增强 — 支持 mermaid 图形渲染（流程图/时序图等，渲染失败降级为代码文本）；右侧可折叠标题目录（TOC），点击快速跳转到对应标题
- Markdown frontmatter 属性面板 — 文档开头的 YAML frontmatter（`---\n...\n---`）不再被当作普通正文渲染，而是解析为正文上方的结构化属性表格：数组值显示为标签徽章，标量值原样展示，嵌套对象以 JSON 文本呈现；解析失败时降级为带语法高亮的 YAML 原文代码块，不影响正文
- HTML 渲染预览 — `.html/.htm` 文件默认以浏览器渲染效果展示（iframe 所见即所得）：页面内 JavaScript 可执行但经 sandbox 隔离（`allow-scripts` 且不带 `allow-same-origin`，无法访问应用主页面与 Wails 绑定方法）；同目录树相对资源（css/js/图片/字体）经后端 `/preview-raw` 白名单路由自动加载；渲染视图内相对链接可在面板内跳转、http(s) 外链用系统浏览器打开；工具栏提供「源码/渲染」切换（源码态可编辑保存，保存后回到渲染视图）与「刷新」按钮（外部修改后重载）；超过 1MB 走超大降级提示
- 文件大小限制（1MB）
- 剪切/复制/粘贴操作
- 拷贝到对话框（支持预览效果）
  - 自定义目标文件名 — 文件与目录（含文件夹本身，即勾选「包含文件夹本身」）拷贝时均可在对话框中修改目标名，默认与源同名；仅拷贝目录内容时自定义名被忽略；同名冲突沿用自动加 (1) 策略
  - 拷贝自动去除只读属性 — 源文件/目录为只读时，拷贝出的目标自动变为可写（含目录递归），源文件属性不变
- 用默认程序打开文件
- 右键菜单操作（新建文件/文件夹、重命名、删除、剪切/复制/粘贴、拷贝到、复制路径/文件名、在资源管理器中打开、用 VSCode/Warp 打开、用 Obsidian 打开、更新仓库、跳转仓库统计（仅 git 仓库节点显示，空白区右键在当前工作目录为 git 仓库时显示））
- 用 Obsidian 打开：文件夹→以自身作为仓库，文件→以父目录作为仓库
- 打开前预检：读取 Obsidian 仓库注册表（%APPDATA%\obsidian\obsidian.json）判断目录是否属于已注册 vault；未注册时弹三按钮确认框提供两条路径，避免 Vault not found 错误；注册表读取失败则降级为现状尽力打开
  - 「自动注册并打开」：二次确认（预告首次打开信任提示、配置已备份、运行中需关闭）后，检测 Obsidian 进程未运行则自动向 obsidian.json 追加 vault 条目（备份+原子写，保留未知顶层字段）并发 URI 打开；运行中则提示关闭后重试（不强制杀进程）。**注意：Obsidian 运行时持有 vault 列表内存缓存，运行中写入会被其退出/切换仓库时回写覆盖导致注册丢失，故自动注册必须在 Obsidian 未运行时进行；首次打开新注册仓库仍会弹「Do you trust the author」信任提示，需用户手动确认。**
  - 「打开仓库管理器」：复制目录路径到剪贴板并跳转 obsidian://choose-vault 手动添加
- 按节点类型区分菜单项（文件夹/文件显示不同操作）

## 4. Git集成

- 查看仓库信息（分支、远程、提交历史）
- 克隆远程仓库（HTTPS/SSH）
- 拉取更新
- 切换分支（ContentPanel「切换分支」弹窗，列出本地/远程分支并切换）
- 分支管理（GitBranches 面板，对齐 GitTags/GitRemotes 范式）：列出本地分支（标记当前分支，远程分支不展示）；从当前 HEAD 创建分支（`git branch <name>`）；删除分支（`git branch -d`，未合并失败后二次确认走 `-D` 强删，当前分支禁删）；重命名本地分支（`git branch -m <old> <new>`，仅本地不触远程）
- 查看本地变动列表（单表分组：未暂存组在上、已暂存组在下，`Staged` 字段驱动；IDEA commit 窗口风格）
- 单文件暂存/取消暂存（工作区整理）：行级「+暂存」（`git add -- <file>`）/「-取消暂存」（`git restore --staged -- <file>`，统一命令通配已跟踪/未跟踪，git 2.25+）；批量「暂存选中/取消暂存选中」并入「更多」下拉；暂存与提交语义解耦——勾选=提交集合，暂存=工作区整理辅助
- 文件差异比较（diff）：双击变动文件，弹窗以左右双栏对照展示差异（已跟踪文件对比 HEAD，未跟踪文件展示为新增全文；二进制、图片、超大文件给出友好提示）
- 外部 diff 工具打开：diff 弹窗（工作区差异 / 提交文件差异 / 区间差异）提供「用外部工具打开」按钮，调用设置中配置的外部 diff 工具对比左右版本（工作区差异右侧直接传工作区原文件，用户可在工具中编辑保存；提交/区间差异两侧由后端生成临时文件）；工具未配置时按钮置灰并提示，路径无效或启动失败经结构化错误码提示（E_DIFF_TOOL_NOT_CONFIGURED 引导去设置 / E_DIFF_TOOL_LAUNCH_FAILED）；配置入口在「设置 - 通用 - 外部 diff 工具」：预设模板（Beyond Compare / WinMerge / VSCode diff / 自定义命令行）选中即填充默认路径与参数模板（{left} {right} 占位符），均可手动修改
- 三向合并工具打开：合并/变基/拣选冲突面板的冲突文件行提供「外部合并」按钮，拉起外部三向合并工具（base/local/remote 三版本由后端从 index stage `:1:`/`:2:`/`:3:` 提取写临时文件，merged 直接为工作区原文件，用户在工具中编辑保存即写回工作区，保存后点「标记已解决」（git add）衔接存量链路）；add/add 冲突无共同祖先时 base 降级空文件；delete/modify 冲突（工作区文件已删除）报错引导先恢复；三向参数模板按预设名自动内置（Beyond Compare / WinMerge / VSCode / KDiff3 / Meld，与 git mergetools 官方口径一致，零配置），自定义工具在「设置 - 通用 - 外部 diff 工具 - 三向合并参数模板」填写（{base} {local} {remote} {merged} 占位符）；VSCode 合并视图需开启 `git.mergeEditor` 设置；临时文件复用外部 diff 的生命周期策略（启动后不删、下次应用启动清理）
- 选择性提交（commit）：通过复选框勾选本次要提交的文件，输入提交信息后点击【提交】，仅提交勾选文件（pathspec 语义，未勾选文件保持未提交）
- 提交并推送、推送到远程（push）：当前分支无上游时弹确认是否 `git push --set-upstream origin <分支>`，凭证透传系统 git 配置；推送输出超过 200 字符时弹独立结果面板完整展示（不截断），并提供复制按钮，短输出仍以消息提示反馈
- 标签管理：列出仓库所有标签（区分轻量/注释，展示指向提交 SHA、注释消息、标注者、相对时间）；创建轻量标签（无消息）与注释标签（`-a -m`，仅钉 HEAD）；删除本地标签；推送单个标签到远程（`git push origin <tag>`）与「推送全部标签」（逐个推送并汇总成功/失败计数）
- 远程仓库管理：列出 remote（名称 + 首个 URL，按 remote 名去重）；新增/删除 remote；拉取远程更新（`git fetch`，可选 `--prune` 清理远端已删分支，支持单 remote 与全部）；为当前分支设置上游跟踪分支（`git branch --set-upstream-to=<remote>/<branch>`，分离头指针时禁用）
- 合并 / 变基 / 拣选 / 冲突解决（GitMerge 面板，对齐 GitBranches/GitTags/GitRemotes 范式）：合并支持 ff/no-ff/squash 三策略（`git merge`），合并前校验工作区干净与非 detached HEAD；变基到目标分支（`git rebase <branch>`），中途冲突支持 `--continue`/`--abort`/`--skip`；Cherry-pick 单提交拣选（`git cherry-pick <sha>`），冲突支持 `--continue`/`--abort`；Pull 入口可选 rebase 模式（`git pull --rebase`，`useRebase` 默认 false 保持原 pull 行为）；冲突解决展示冲突文件列表（`git diff --name-only --diff-filter=U`），「打开」调外部编辑器手动改冲突标记、「标记已解决」执行 `git add`，全部解决后 continue 提交，merge/rebase/cherry-pick 各自提供 abort 逃生口，不做内置三方合并编辑器
- 子模块管理（GitSubmodules 面板，对齐 GitTags/GitRemotes 范式）：查看子模块列表（`git submodule status` + `git status --porcelain=2` 双命令融合，按 path 关联产出 path/SHA/describe/branch/url/initialized/dirty/shaMismatch/conflict/detached 等状态字段）；四色状态标签（灰=未初始化、绿=干净、橙=已修改或 SHA 未同步、红=冲突）+ detached HEAD 警告标记；初始化（`git submodule update --init`）；更新（checkout/merge/rebase/remote 四模式 + recursive + init 开关，支持全量与单行 subPath）；添加（`git submodule add [-b branch] <url> <path>`，branch 可空走默认分支）；删除（deinit -f + git rm -f + 显式清理 `.git/modules/<name>` 三步，二次确认防误删）；detached 子模块行内「切换跟踪分支」（读 `.gitmodules` 的 branch 配置，`git -C <path> checkout <branch>`，未配置跟踪分支时按钮禁用并提示）
- 回滚变动：保留对勾选文件的回滚入口（含二次确认），下沉到「更多」下拉菜单
- 提交/推送后联动刷新本地变动列表、提交历史与仓库信息
- 丢弃本地更改
- 分页查看提交历史（默认10条/页）
- 分支同步摘要条（提交历史面板 header）：展示当前分支名 + 领先/落后上游计数（↑ahead 未推送 danger 色 / ↓behind 未拉取 warning 色，语义对齐全局状态看板），远程头所在 commit 一眼可见——提交行按 SHA 匹配渲染 refs 标签（当前分支 primary / 上游 origin/xxx info / 分离 HEAD danger，本地与远程头重合时同行共标）；ahead>0 一键推送（复用推送流程，无上游时确认 set-upstream），behind>0 split 下拉拉取（主按钮 rebase、下拉项 merge），fetch 小按钮刷新远程引用后重算摘要与 badge（失败仅提示不阻塞）；behind 基于上次 fetch 的本地远程引用快照（tooltip 标注时效），push/pull/fetch 成功后摘要与提交列表自动刷新；无上游（仅分支名 + 推送引导）、detached HEAD（分离头指针提示）、空仓库等边界降级展示不报错
- 批量更新仓库（递归扫描子目录，并行拉取，实时进度展示；未配置远程的本地仓库自动跳过，不计失败）
- 工作目录直显仓库详情：在左栏选中一个 git 仓库工作目录时，右侧操作面板直接显示该仓库的仓库信息、提交历史、本地变动（与在文件树中选中 git 仓库节点一致），无需再到文件树点选；非 git 工作目录选中后保持原空状态
- 并发操作控制：变更类 Git 操作（commit/push/pull/checkout/merge/rebase/cherry-pick/stage/discard/分支增删改/标签/远程/fetch 等）按仓库路径串行化，同一仓库已有变更操作进行中时，后续请求立即被拒绝并提示「该仓库有 Git 操作进行中，请稍后重试」（前端统一 `ElMessage.warning`，非 `error`）；不同仓库操作互不阻塞，只读操作（查看分支/变动/diff/冲突状态等）不受影响；BatchPull 内部并发 worker 与手动单仓操作抢同一仓锁，冲突方记为失败

- 仓库统计：活动栏一级入口（仓库统计面板），复用提交历史缓存聚合可视化，不重复扫 git log——提交趋势图（按日/周/月聚合，固定档位 7天/30天/90天/1年/全部，粒度随档位自动适配：7天/30天按日、90天/1年按周、全部按月）、活跃度热力图（类 GitHub 草地，最近一年按日，5 档色阶 visualMap）、贡献者排名（横向柱状，卡片内「提交数/行数」维度切换器：提交数视图按提交数降序，行数视图按总变更行数（新增+删除）降序、tooltip 展示 +新增/−删除 细分，同名不同邮箱视为不同贡献者）、行数分布（横向柱状，卡片内「目录/文件」维度切换器：目录视图按一级目录上卷展示全量降序看模块分布，文件视图展示 Top 15 热点文件，tooltip 展示 +新增/−删除 细分与完整路径，rename 提交路径归一为新路径（`old => new` 取 new、`{a => b}/x.go` 归一为 `b/x.go`），二进制文件行不计入）；行数数据走独立 `git log --numstat` 通道（`service/commit_line_stats.go`），按作者聚合新增/删除行数（二进制文件行不计入、merge commit 计 0 行），文件路径明细供行数分布聚合（`service/commit_path_stats.go`），独立行数缓存与提交历史缓存同键（HEAD SHA 相同 + 5min TTL 内命中，否则全量重拉，无增量路径），拉取受 5000 条上限约束与提交历史采样口径对齐，行数窗口过滤与提交数共用同一档位窗口实现；超限仓库（>5000 commit）取最近 5000 条采样统计并提示用户（TotalCommits/贡献者为采样值）；统计直接吃 `commit_history_cache` 全量快照，与 `GetCommitHistory` 共享命中/增量/全量三态解析
  - 当前仓库信息条：统计页顶部展示当前统计所对应仓库的信息（仓库名 + 路径 + 当前分支 + 远程地址），分支/远程地址复用「仓库信息」面板的 `git-info` 缓存键（用户看过该仓库信息 tab 即命中零调用）；仅统计页可见时加载，与统计数据同步随选中节点/面板切换刷新
  - 一键跳转入口：工作目录右键（仅 git 仓库工作目录）与文件树右键（git 仓库目录节点，或空白区右键且当前工作目录为 git 仓库）提供「跳转仓库统计」菜单项，点击后设当前选中节点为该仓库并切换到统计面板，StatsView 自动加载该仓库统计
  - 全局状态看板：活动栏一级入口（状态看板图标），手动 pin 关注的核心仓库跨仓状态总览（不全局扫描所有仓库，开源仓等不关注的不进看板）。每行展示仓库名 / 当前分支（detached HEAD 标「分离头指针」并显示短 SHA）/ 工作区（干净/有改动）/ 未推送提交数 ahead / 未拉取提交数 behind / 上游状态（无上游标记）；ahead/behind 基于 `git rev-list --left-right --count @{u}...HEAD` 算本地远程引用（上次 fetch/clone 快照），看板不主动 fetch，behind 为「相对上次 fetch」的近似值，顶部信息图标标注时效；点击行跳转该仓（切工作目录 + 展开文件树定位，复用仓库筛选器跳转范式）；失效仓库（pin 后路径删除）标 Missing 灰显不阻塞。双入口添加 pin：①看板「添加仓库」弹窗选工作目录→扫描→多选批量加入；②工作目录/文件树 git 仓库节点右键「加入状态看板」单仓随手 pin（已 pin 时转为取消关注）。pin 列表独立持久化 `data/dashboard_pinned.json`（路径 `filepath.Abs` 规范化去重），与仓库筛选器元数据（`repo_meta.json` 简述/标签）职责分离。状态计算只读不走仓级锁，批量并发复用 `HasRemotesBatch` 范式

## 9. AI 功能（Skill 聚合）

活动栏一级入口「AI 功能」占满主区（与工作目录/工具箱互切，切换间任务状态保留），将散落各项目的 Claude Code skills 聚合为可视化功能菜单。点击左侧功能卡片打开功能 Tab（详情 + 参数录入 + 运行按钮），运行后输出在任务 Tab 流式回显。

### 功能列表筛选与排序

- 侧栏搜索框按名称/描述/标签模糊匹配，下方 tag chips 多选筛选（含全部选中标签）
- 排序优先级：**置顶（pinned）> 使用频次（开关开启时）> 配置文件顺序**；搜索框右侧「频次」开关切换频次排序模式，选择持久化到 localStorage（记住上次状态）
- 频次 = 功能项在运行历史归档中的运行次数（成功/失败/超时计入，取消不计入），后端聚合为 `functionId → 次数` 后轻量过 IPC，列表先渲染、频次到达后重排不阻塞
- 频次模式开启时功能卡片展示运行次数角标（如 `12 次`），关闭时隐藏避免视觉噪音

### 执行机制

- 后端对每个功能项起 `claude -p` headless 子进程，`--output-format stream-json` 流式回显到输出面板
- 子进程 `cwd` 设为 skill 所在项目根（项目级 skill 与该项目的 settings/env 原样生效，skills 不迁移；腾讯会议功能依赖 u54 项目 settings 的 token，skill 会话内经其自带 tm.py 脚本直调 API）
- `--add-dir` 授予额外目录读权限；`--mcp-config`/`--settings` 内联注入 MCP server（http/stdio）与环境变量为通用能力（支持 `$ENV:VAR` 引用宿主环境变量）
- 任务可取消（taskkill 杀进程树）、可超时（功能项配置分钟数，默认 10），多任务并行、每任务一 Tab；同功能重复运行复用其空闲任务 Tab（后续段仍新开 Tab 保留历史）

### 可观测性与并发治理

- **任务计量**：result 事件解析耗时/轮次/成本（`total_cost_usd`）+ token 用量四项，任务完成态底栏展示耗时 · 入出 token · 缓存读 · 成本 · 轮次
- **并发上限**：全局信号量限制同时运行 3 个 claude 子进程（防本地资源抢占与 API 限流），超限任务排队等待、标题栏展示「N/M（排队 K）」；超时起算后移到获取槽位后，排队等待不侵蚀执行预算
- **输出治理**：前端末尾窗口 256KB 截断（流式过程不卡顿，顶部提示省略量）；后端输出流式写文件 `data/ai_task_output/<id>.txt`（不再 `strings.Builder` 全量驻留），`GetAiTaskState` 返回末尾 ~4KB 预览 + 字节数 + 文件路径；copy/预览/表格视图经 `GetAiTaskOutput` 全量读取，不依赖已截断的展示文本
- **表格预解析**：`GetAiTaskState`/`ai-task:done` 预解析输出中的 markdown 表格为 `TableExtracted`（表头 + 行映射），表格视图直接用，避免截断后表格丢失

### 运行历史归档

- 任务完成（成功/失败/取消/超时）后自动归档：输出文件经 `os.Rename` 零拷贝移入 `data/ai_task_history/<id>.txt`，元数据追加 `data/ai_task_history.json`（复用计量字段，无大对象过 IPC）
- 标题栏「历史」打开历史面板：按功能/时间范围/状态筛选，列表展示时间 · 功能 · 状态 · 耗时 · 成本 · 输出大小，点击「查看输出」懒加载读取归档输出全文，支持单条删除与「清理 30 天前」批量清理
- 保留策略：默认 2000 条 + 90 天双上限（先到先清理最旧）；定时清理 1 天前未归档的运行期输出文件兜底防孤儿；session_id 存入历史元数据供事后 `--resume`（入口后续补）

### 历史统计与导出

- 历史面板顶部统计卡片区随筛选查询一并刷新：运行次数（含成功数） · 总成本 · 总 token（入/出/缓存读/缓存写四分项相加，悬停看分项明细） · 总耗时；下方功能排行表展示每个功能的运行次数与总成本（按次数降序）
- 一键导出当前筛选范围（所见即所导）：「导出 CSV」生成明细 CSV（UTF-8 BOM，Excel 中文兼容，列含时间/功能/状态/耗时/成本/入出 token/输出大小）；「导出 Markdown」生成报告（统计摘要 + 功能排行 + 明细三张表）；落盘经系统保存对话框由用户选路径，后端不直接写文件

- 功能项存 `data/ai_functions.json`：id/名称/斜杠命令/cwd/授权目录/环境变量/MCP 定义/权限模式/超时/完成动作/参数规格（none/file/text/form）/后续段

## 10. AI 对话

活动栏一级入口「AI 对话」占满主区（与工作目录/AI 功能/工具箱等面板互切），提供以常用目录为入口的多会话持续式 AI 对话。与「AI 功能」面板的定位区别：「AI 功能」是技能的一次性触发（选功能、填参数、看输出），「AI 对话」是多轮持续对话（选目录、发需求、流式回复、续会话），默认走 claude code CLI，provider 接口预留多 CLI 接入。

### 常用目录管理

- 侧栏「常用目录」是 AI 对话的入口单位，每个目录项对应一个 claude 子进程工作目录（cwd）
- 添加：面板「添加目录」按钮手输路径；或工作目录右键「添加到 AI 对话」加整个工作目录、文件树目录节点右键「添加到 AI 对话」加该子目录；重复路径幂等返回既有项并提示
- 显示名：添加时可自定义（如「项目管理」，留空取目录名），侧栏项 hover 出「重命名」入口可改，仅改展示不影响路径与会话
- 排序：拖拽重排，顺序持久化；移除：hover 出「移除」按钮 + 二次确认（仅移出侧栏，该目录的会话与消息数据不受影响）

### 会话管理（类 /resume）

- 每个目录下可建多个会话，「新建会话」一键创建（默认标题「新会话」）；无会话时直接输入发送会自动先建会话
- 会话历史下拉按钮查看会话列表（标题 + 最近活跃时间，按活跃降序），点击切换进入历史会话；支持删除当前会话（二次确认，消息一并删除）
- 发送首条消息时自动以消息前 20 字生成会话标题（标题已被用户改过则不覆盖）
- claude 侧 `--resume <sessionId>` 续上下文：同会话二次提问自动携带上一轮 claude session id，多轮上下文连贯；WorkBench 持久化会话元数据（`data/ai_chat/sessions.json`）与每轮消息（`data/ai_chat/messages/<sessionId>.json`），重启可恢复
- 在途任务时切换目录/会话弹确认（「取消任务并切换」，走 CancelChatTask 杀进程树，防旧结果串入新会话）

### 对话

- 输入框 Enter 发送 / Shift+Enter 换行；发送后任务排队（AI 对话独立并发槽位，与 AI 功能任务互不挤占，上限 3 个 claude 子进程）→ 运行 → 流式增量输出
- 回复区上下气泡排版（用户右侧主色淡底 / AI 左侧弱层底），流式生成中气泡尾部闪烁光标，完成后 markdown 渲染（标题/列表/代码块/表格/引用，关闭原始 HTML 防 XSS）
- 运行中「发送」按钮切换为「停止」，点击取消任务（杀 claude 及其子进程树）；面板切走再切回自动恢复在途任务状态（防 loading 卡死）

### 选择题交互卡片

- AI 需要用户做单选/多选决策时（如「部署到测试还是生产？」），回复中以 `chat-question` 代码块承载问题与选项，前端自动渲染为消息内的**交互卡片**：问题标题 + 选项按钮，`multiSelect: true` 的题标注「可多选」
- 点选选项（单选 radio 语义，多选可切换多个），每题至少选一项后「发送选择」按钮启用；点击提交即以结构化文本发送新一轮对话（走常规 `--resume` 链路回传模型），卡片置灰防重复作答
- 卡片内联于消息流、非弹窗：等待选择时可自由切换会话/目录/面板，不阻塞任何导航；该会话有对话进行中时提交按钮置灰，任务结束后恢复
- 已答标记为内存态：切换会话往返保留置灰，应用重启后卡片恢复未答可再点
- 非法/不完整的选择题块按普通代码块显示，文字提问走普通对话不受影响
- 实现约束：无头模式下 claude 的 AskUserQuestion 工具不可交互（被 CLI 自动应答），ChatService 已全局禁用该工具并在首轮注入声明引导模型改用 `chat-question` 块

### 模板

- 输入框旁「模板」下拉分「本目录模板 / 全局模板」两组（当前目录无模板时仅展示全局组）；模板为纯文本片段，点击整段填入输入框可再修改后发送
- 尾部「管理模板」打开弹窗：列表 + 表单增删改（名称/归属本目录或全局/内容），归属域创建后不可改（换归属删旧建新）；目录模板归属侧栏目录项，目录项移除后其模板不再展示

### 执行配置

- 对话页顶部下拉切换权限模式与模型，选择持久化记忆（`data/ai_chat/settings.json`），重启恢复
- 权限模式四档：默认权限（default，claude 默认行为，敏感操作逐次确认）/ 自动接受编辑（acceptEdits，文件编辑自动接受）/ 规划模式（plan，仅分析与规划不执行修改）/ 跳过确认（bypassPermissions，AI 可直接修改代码与执行命令——**高危**，选中时立即警告提示）
- 模型下拉：默认模型（空 = claude CLI 默认）/ Sonnet / Opus / Haiku，支持自定义输入

## 11. 浏览器访问

同一 WorkBench 进程可将完整界面暴露为浏览器可访问页面，用于从本机其他浏览器或远程设备交互管理本地文件、Git、终端与 AI 任务。浏览器端与桌面窗口功能完全一致（文件、Git、终端、AI 任务全功能可用），业务界面零差异。

### 11.1 访问模式

| 模式 | 触发方式 | 行为 |
| --- | --- | --- |
| 桌面同开（默认） | 正常启动应用（双击 exe / `wails dev`） | 桌面窗口照常运行，后台同时开启 HTTP 服务；可在设置「网络访问」中关闭 |
| 无头服务 | 命令行启动 `workbench.exe --serve` | 跳过桌面窗口，纯 HTTP 服务常驻运行，适合远程访问与开机自启 |

- 服务默认绑定回环地址 `127.0.0.1:36115`，仅本机浏览器可达
- 绑定地址可在设置「网络访问」分区修改，或以 `--listen=<host:port>` 命令行参数覆盖（命令行优先于配置文件）
- 桌面同开模式下端口占用等启动失败仅记录警告日志并降级（不影响桌面功能）；`--serve` 模式监听失败则进程退出

### 11.2 访问令牌（token 认证）

浏览器访问采用单令牌认证，令牌必开、无匿名访问：

| 环节 | 行为 |
| --- | --- |
| 首次生成 | 首次启动自动生成随机令牌，持久化到 `data/web_token`（文件权限 0600，仅属主可读写） |
| 设置页查看 | 设置「网络访问」分区默认遮蔽显示，支持「显示 / 复制 / 重新生成」 |
| 重新生成 | 点击「重新生成」立即热轮换：旧令牌随即失效，已建立的浏览器连接保持至断开重连 |
| 浏览器首访 | 浏览器打开 `http://<地址>/?token=<令牌>` 即完成验证并自动建立 30 天 cookie 会话（`wb_token`，HttpOnly），后续页面、静态资产、RPC 与 WebSocket 请求全部自动携带会话，无需再次输令牌；令牌轮换后旧会话失效，须以新令牌重新验证 |
| 认证范围 | 除健康检查 `/healthz` 外，HTTP 与 WebSocket 请求均须携带令牌（缺失或错误令牌一律拒绝）；凭据优先级为 Authorization 头 > X-Auth-Token 头 > wb_token cookie > `?token=` 查询参数（仅首次手工验证用），令牌不进入日志，规避泄漏 |

### 11.3 设置页「网络访问」分区

设置面板「网络访问」标签页集中管理浏览器访问通道：

| 设置项 | 说明 |
| --- | --- |
| 浏览器访问开关 | 控制桌面模式是否同开 HTTP 服务（默认开启），关闭后立即停机 |
| 绑定地址 | 分段按钮快捷切换「本地 127.0.0.1 / 公网 0.0.0.0」（端口沿用当前值；切公网弹风险确认，切本地直接生效），或手输自定义 `host:port`（手输自定义地址时分段置空）；改绑非回环地址（如 `0.0.0.0`）弹风险确认——本机全部文件、终端与 AI agent 能力将暴露给局域网设备，且服务未内置 TLS，远程访问建议使用 Tailscale / frp 等加密隧道 |
| 运行状态 | 实时展示 HTTP 服务「运行中 / 已停止」 |
| 访问令牌 | 遮蔽显示，支持显示 / 复制 / 重新生成（热轮换） |
| 访问地址 | 服务运行时展示候选地址列表（含回环与本机局域网 IPv4，永不包含 `0.0.0.0`），局域网地址仅同网段设备可达；每行「复制链接」一键复制 `http://<地址>/?token=<令牌>` 完整链接，粘贴浏览器即用——链接内含令牌即凭据，请勿外发 |

### 11.4 断线重连

浏览器端与后端的连接中断后自动恢复，无需手动刷新页面：

- WebSocket 断开后按指数退避自动重连（1 秒起步、2 倍递增、30 秒封顶），断连期间页面顶部展示「与后端连接已断开，正在自动重连…」横幅，重连成功后自动消失
- 事件订阅常驻不清空，重连成功后事件分发自动恢复，无需重新订阅
- 因令牌重新生成导致认证失败（401）时，弹出令牌输入门，输入新令牌后自动继续（下一次重连即使用新令牌）

## 12. 状态管理架构

前端引入 Pinia 统一管理全局响应式状态，采用 **setup store** 写法（`defineStore('id', () => {...})`），按状态内聚拆分为 6 个域 store。store 只承载响应式数据与数据操作，不承载命令式跨组件调用。

### 6 个 store 职责

| store | 职责 |
| ---- | ---- |
| favorites | 收藏夹列表，封装加载/增删/改别名/改分组/搜索，调用后端 wailsjs 绑定 |
| settings | 快捷键配置（4 项 ref + load/save/checkConflict）+ 主题态（themeMode 三态 + resolvedTheme computed + matchMedia 监听 + load/saveTheme）+ 无状态纯函数（parseShortcut/matchShortcut/isValidShortcut 等）命名导出 |
| ui | UI 临时态：activePanel、终端三件套（visible/height/dir）、弹窗 visible、appVersion |
| directory | 工作目录：directories 列表、selectedDirectoryId、currentDirPath computed + load/refresh/select/locate 逻辑 |
| workspace | 工作区共享态：selectedNode、latestCommit、clipboard、lastInteractedTree |
| aiChat | AI 对话全域：常用目录（列表/选中/增删改排序）、会话（列表/选中/消息）、在途任务态（chat-task:* 事件驱动）、模板（目录+全局合并）、执行配置（权限模式/模型） |

### 设计原则

- **store 管数据，ref 管命令** — store 只承载响应式数据；命令式跨组件调用（`FileTreePanel.refreshNode/previewFile/locateNode`、`ContentPanel.clearPreview/startBatchPull`、`DirectoryTree.closeMenu/triggerRenameCurrent` 等）仍走 template ref + defineExpose，由 Home.vue 中介调度，不进 store。
- **子组件直读 store，删除 prop 透传** — 子组件按需 import 对应 store，不再经 Home.vue props 下发；Home.vue 从持有约 20 个本地 ref 的"上帝组件"收敛为跨域编排容器。
- **保留两类 composable** — `useCommandPalette` / `useTerminal` 为工厂函数、每实例独立状态，属组件内实例态，不迁 store；`useRecentAccess` / `useTreeState` 为 localStorage 纯工具函数，无共享 ref，保留供 store 与组件调用。

### HMR 与入口注册

- 每个 store 文件末尾配置 `acceptHMRUpdate`，开发热更新保留状态不重置。
- `store/index.js` 创建 pinia 实例并 re-export 6 store，`main.js` 经 `app.use(pinia)` 注册。
