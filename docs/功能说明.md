# WorkBench 功能说明

## 1. 工作目录管理

- 添加/删除/更新工作目录
- 设置默认目录
- 拖拽排序目录顺序
- JSON持久化配置
- 路径验证（Windows格式）
- 右键菜单：重命名（F2）、设为默认、复制路径、在资源管理器中打开、用 VSCode 打开、用 Warp 打开、用 Obsidian 打开（以该目录作为 Obsidian 仓库）、更新仓库、删除（Delete）
- Git 仓库标记：本身是 git 仓库的工作目录项显示 git 图标；已配置远程显示彩色 git.png，未配置远程显示灰色 git-gray.png，便于一眼识别

## 2. 文件树浏览

- 懒加载机制（按需加载子节点）
- Git仓库自动检测（git 图标标识，彩色/灰色区分有无远程）
- .git文件夹过滤
- 全部展开/收起功能
- 节点选择和高亮
- 点击祖先目录时仅选中不收起（向上导航保护）

## 3. 文件操作

- 创建文件/文件夹
- 重命名、删除
- 文件预览（支持文本/二进制检测）
- unsupported 按文本预览 - 无扩展名或未知扩展名文件优先尝试按文本读取（UTF-8 优先 + GBK 兜底解码），可显示则降级为文本预览；含 NUL 字节或解码失败的二进制文件、超大文件（>1MB）走降级提示
- 文件预览编辑 — 预览文本文件时可就地编辑，修改后保存或取消，切换文件时自动检查未保存修改；编辑态支持 Ctrl+S 保存、Esc 取消（有未保存修改时二次确认）；保存按原文件编码（UTF-8/GBK）写入，不改变原文件编码（GBK 文件编辑后仍为 GBK）
- Markdown 预览链接导航 — 相对引用（./other.md、../readme.md）在预览面板内切换预览；外部 http 链接用系统浏览器打开；同文档锚点（#标题）滚动定位
- Markdown 预览增强 — 支持 mermaid 图形渲染（流程图/时序图等，渲染失败降级为代码文本）；右侧可折叠标题目录（TOC），点击快速跳转到对应标题
- Markdown frontmatter 属性面板 — 文档开头的 YAML frontmatter（`---\n...\n---`）不再被当作普通正文渲染，而是解析为正文上方的结构化属性表格：数组值显示为标签徽章，标量值原样展示，嵌套对象以 JSON 文本呈现；解析失败时降级为带语法高亮的 YAML 原文代码块，不影响正文
- HTML 渲染预览 — `.html/.htm` 文件默认以浏览器渲染效果展示（iframe 所见即所得）：页面内 JavaScript 可执行但经 sandbox 隔离（`allow-scripts` 且不带 `allow-same-origin`，无法访问应用主页面与 Wails 绑定方法）；同目录树相对资源（css/js/图片/字体）经后端 `/preview-raw` 白名单路由自动加载；渲染视图内相对链接可在面板内跳转、http(s) 外链用系统浏览器打开；工具栏提供「源码/渲染」切换（源码态可编辑保存，保存后回到渲染视图）与「刷新」按钮（外部修改后重载）；超过 1MB 走超大降级提示
- 文件大小限制（1MB）
- 剪切/复制/粘贴操作
- 拷贝到对话框（支持预览效果）
  - 自定义目标文件名 — 文件与目录（含文件夹本身，即勾选「包含文件夹本身」）拷贝时均可在对话框中修改目标名，默认与源同名；仅拷贝目录内容时自定义名被忽略；同名冲突沿用自动加 (1) 策略
  - 拷贝自动去除只读属性 — 源文件/目录为只读时，拷贝出的目标自动变为可写（含目录递归），源文件属性不变
- 用默认程序打开文件
- 右键菜单操作（新建文件/文件夹、重命名、删除、剪切/复制/粘贴、拷贝到、复制路径/文件名、在资源管理器中打开、用 VSCode/Warp 打开、用 Obsidian 打开、更新仓库）
- 用 Obsidian 打开：文件夹→以自身作为仓库，文件→以父目录作为仓库
- 打开前预检：读取 Obsidian 仓库注册表（%APPDATA%\obsidian\obsidian.json）判断目录是否属于已注册 vault；未注册时弹三按钮确认框提供两条路径，避免 Vault not found 错误；注册表读取失败则降级为现状尽力打开
  - 「自动注册并打开」：二次确认（预告首次打开信任提示、配置已备份、运行中需关闭）后，检测 Obsidian 进程未运行则自动向 obsidian.json 追加 vault 条目（备份+原子写，保留未知顶层字段）并发 URI 打开；运行中则提示关闭后重试（不强制杀进程）。**注意：Obsidian 运行时持有 vault 列表内存缓存，运行中写入会被其退出/切换仓库时回写覆盖导致注册丢失，故自动注册必须在 Obsidian 未运行时进行；首次打开新注册仓库仍会弹「Do you trust the author」信任提示，需用户手动确认。**
  - 「打开仓库管理器」：复制目录路径到剪贴板并跳转 obsidian://choose-vault 手动添加
- 按节点类型区分菜单项（文件夹/文件显示不同操作）

## 4. Git集成

- 查看仓库信息（分支、远程、提交历史）
- 克隆远程仓库（HTTPS/SSH）
- 拉取更新
- 切换分支
- 查看本地变动列表（单区变动清单，IDEA commit 窗口风格）
- 文件差异比较（diff）：双击变动文件，弹窗以左右双栏对照展示差异（已跟踪文件对比 HEAD，未跟踪文件展示为新增全文；二进制、图片、超大文件给出友好提示）
- 选择性提交（commit）：通过复选框勾选本次要提交的文件，输入提交信息后点击【提交】，仅提交勾选文件（pathspec 语义，未勾选文件保持未提交）
- 提交并推送、推送到远程（push）：当前分支无上游时弹确认是否 `git push --set-upstream origin <分支>`，凭证透传系统 git 配置
- 标签管理：列出仓库所有标签（区分轻量/注释，展示指向提交 SHA、注释消息、标注者、相对时间）；创建轻量标签（无消息）与注释标签（`-a -m`，仅钉 HEAD）；删除本地标签；推送单个标签到远程（`git push origin <tag>`）与「推送全部标签」（逐个推送并汇总成功/失败计数）
- 远程仓库管理：列出 remote（名称 + 首个 URL，按 remote 名去重）；新增/删除 remote；拉取远程更新（`git fetch`，可选 `--prune` 清理远端已删分支，支持单 remote 与全部）；为当前分支设置上游跟踪分支（`git branch --set-upstream-to=<remote>/<branch>`，分离头指针时禁用）
- 回滚变动：保留对勾选文件的回滚入口（含二次确认），下沉到「更多」下拉菜单
- 提交/推送后联动刷新本地变动列表、提交历史与仓库信息
- 丢弃本地更改
- 分页查看提交历史（默认10条/页）
- 批量更新仓库（递归扫描子目录，并行拉取，实时进度展示；未配置远程的本地仓库自动跳过，不计失败）
- 工作目录直显仓库详情：在左栏选中一个 git 仓库工作目录时，右侧操作面板直接显示该仓库的仓库信息、提交历史、本地变动（与在文件树中选中 git 仓库节点一致），无需再到文件树点选；非 git 工作目录选中后保持原空状态

- 设置项自动保存持久化

## 9. AI 功能（Skill 聚合）

活动栏一级入口「AI 功能」占满主区（与工作目录/工具箱互切，切换间任务状态保留），将散落各项目的 Claude Code skills 聚合为可视化功能菜单。点击左侧功能卡片打开功能 Tab（详情 + 参数录入 + 运行按钮），运行后输出在任务 Tab 流式回显。

### 功能列表筛选与排序

- 侧栏搜索框按名称/描述/标签模糊匹配，下方 tag chips 多选筛选（含全部选中标签）
- 排序优先级：**置顶（pinned）> 使用频次（开关开启时）> 配置文件顺序**；搜索框右侧「频次」开关切换频次排序模式，选择持久化到 localStorage（记住上次状态）
- 频次 = 功能项在运行历史归档中的运行次数（成功/失败/超时计入，取消不计入），后端聚合为 `functionId → 次数` 后轻量过 IPC，列表先渲染、频次到达后重排不阻塞
- 频次模式开启时功能卡片展示运行次数角标（如 `12 次`），关闭时隐藏避免视觉噪音

### 执行机制

- 后端对每个功能项起 `claude -p` headless 子进程，`--output-format stream-json` 流式回显到输出面板
- 子进程 `cwd` 设为 skill 所在项目根（项目级 skill 与该项目的 settings/env 原样生效，skills 不迁移；腾讯会议功能依赖 u54 项目 settings 的 token，skill 会话内经其自带 tm.py 脚本直调 API）
- `--add-dir` 授予额外目录读权限；`--mcp-config`/`--settings` 内联注入 MCP server（http/stdio）与环境变量为通用能力（支持 `$ENV:VAR` 引用宿主环境变量）
- 任务可取消（taskkill 杀进程树）、可超时（功能项配置分钟数，默认 10），多任务并行、每任务一 Tab；同功能重复运行复用其空闲任务 Tab（后续段仍新开 Tab 保留历史）

### 可观测性与并发治理

- **任务计量**：result 事件解析耗时/轮次/成本（`total_cost_usd`）+ token 用量四项，任务完成态底栏展示耗时 · 入出 token · 缓存读 · 成本 · 轮次
- **并发上限**：全局信号量限制同时运行 3 个 claude 子进程（防本地资源抢占与 API 限流），超限任务排队等待、标题栏展示「N/M（排队 K）」；超时起算后移到获取槽位后，排队等待不侵蚀执行预算
- **输出治理**：前端末尾窗口 256KB 截断（流式过程不卡顿，顶部提示省略量）；后端输出流式写文件 `data/ai_task_output/<id>.txt`（不再 `strings.Builder` 全量驻留），`GetAiTaskState` 返回末尾 ~4KB 预览 + 字节数 + 文件路径；copy/预览/表格视图经 `GetAiTaskOutput` 全量读取，不依赖已截断的展示文本
- **表格预解析**：`GetAiTaskState`/`ai-task:done` 预解析输出中的 markdown 表格为 `TableExtracted`（表头 + 行映射），表格视图直接用，避免截断后表格丢失

### 运行历史归档

- 任务完成（成功/失败/取消/超时）后自动归档：输出文件经 `os.Rename` 零拷贝移入 `data/ai_task_history/<id>.txt`，元数据追加 `data/ai_task_history.json`（复用计量字段，无大对象过 IPC）
- 标题栏「历史」打开历史面板：按功能/时间范围/状态筛选，列表展示时间 · 功能 · 状态 · 耗时 · 成本 · 输出大小，点击「查看输出」懒加载读取归档输出全文，支持单条删除与「清理 30 天前」批量清理
- 保留策略：默认 2000 条 + 90 天双上限（先到先清理最旧）；定时清理 1 天前未归档的运行期输出文件兜底防孤儿；session_id 存入历史元数据供事后 `--resume`（入口后续补）

### 历史统计与导出

- 历史面板顶部统计卡片区随筛选查询一并刷新：运行次数（含成功数） · 总成本 · 总 token（入/出/缓存读/缓存写四分项相加，悬停看分项明细） · 总耗时；下方功能排行表展示每个功能的运行次数与总成本（按次数降序）
- 一键导出当前筛选范围（所见即所导）：「导出 CSV」生成明细 CSV（UTF-8 BOM，Excel 中文兼容，列含时间/功能/状态/耗时/成本/入出 token/输出大小）；「导出 Markdown」生成报告（统计摘要 + 功能排行 + 明细三张表）；落盘经系统保存对话框由用户选路径，后端不直接写文件

### 多段编排（交互确认）

含人工确认环节的功能拆为多段：每段一次独立 `claude -p` 调用，第二段起 `--resume <session-id>` 续会话保留上下文。确认由界面承载：周报草稿完成后点「确认落盘」按钮续段落盘；会议列表以表格展示（含隐藏的时长/入会链接/入会密码列），行内「取消」按钮弹确认框后直接执行取消、「详情」按钮一键复制完整会议信息，无需手输会议号。

### 首批功能

| 功能 | 说明 | 交互 |
| ---- | ---- | ---- |
| 生成周报 | ab-weekly-report（u63 项目） | 直跑出草稿与亮点候选 → 面板确认 → 落盘终稿 |
| 文档转 HTML 发言稿 | agree-slides 插件（u51 项目） | 多选源文档（手输完整路径或浏览树）→ 运行 → 预览 HTML 产物 |

### 配置管理

- 功能项存 `data/ai_functions.json`：id/名称/斜杠命令/cwd/授权目录/环境变量/MCP 定义/权限模式/超时/完成动作/参数规格（none/file/text/form）/后续段
- 面板标题栏「配置管理」支持增删改（常用字段表单化，参数/后续段/env/MCP 以 JSON 编辑），保存即生效；配置为空时自动恢复默认四项
- skill 自动发现与一键导入：配置对话框基础字段区「从已发现 skill 导入」入口扫描用户级 `~/.claude/skills`、各工作目录 `.claude/skills`、已安装插件 `installPath/skills`，解析 `SKILL.md` frontmatter 后列表展示（名称/描述/来源/命令/目录），支持模糊搜索，选中后回填斜杠命令（插件带 `/<plugin>:<name>` 命名空间）与 cwd，免手记命名空间与目录；结果按各源 mtime 缓存，「刷新」按钮强制重扫；导入后用四块表单补全参数/完成动作等字段
- 完成动作：无 / 打开产物目录 / 预览 HTML 产物（从输出提取 .html 路径用系统默认程序打开）/ 复制输出

## 10. 状态管理架构

前端引入 Pinia 统一管理全局响应式状态，采用 **setup store** 写法（`defineStore('id', () => {...})`），按状态内聚拆分为 5 个域 store。store 只承载响应式数据与数据操作，不承载命令式跨组件调用。

### 5 个 store 职责

| store | 职责 |
| ---- | ---- |
| favorites | 收藏夹列表，封装加载/增删/改别名/改分组/搜索，调用后端 wailsjs 绑定 |
| settings | 快捷键配置（4 项 ref + load/save/checkConflict）+ 主题态（themeMode 三态 + resolvedTheme computed + matchMedia 监听 + load/saveTheme）+ 无状态纯函数（parseShortcut/matchShortcut/isValidShortcut 等）命名导出 |
| ui | UI 临时态：activePanel、终端三件套（visible/height/dir）、弹窗 visible、appVersion |
| directory | 工作目录：directories 列表、selectedDirectoryId、currentDirPath computed + load/refresh/select/locate 逻辑 |
| workspace | 工作区共享态：selectedNode、latestCommit、clipboard、lastInteractedTree |

### 设计原则

- **store 管数据，ref 管命令** — store 只承载响应式数据；命令式跨组件调用（`FileTreePanel.refreshNode/previewFile/locateNode`、`ContentPanel.clearPreview/startBatchPull`、`DirectoryTree.closeMenu/triggerRenameCurrent` 等）仍走 template ref + defineExpose，由 Home.vue 中介调度，不进 store。
- **子组件直读 store，删除 prop 透传** — 子组件按需 import 对应 store，不再经 Home.vue props 下发；Home.vue 从持有约 20 个本地 ref 的"上帝组件"收敛为跨域编排容器。
- **保留两类 composable** — `useCommandPalette` / `useTerminal` 为工厂函数、每实例独立状态，属组件内实例态，不迁 store；`useRecentAccess` / `useTreeState` 为 localStorage 纯工具函数，无共享 ref，保留供 store 与组件调用。

### HMR 与入口注册

- 每个 store 文件末尾配置 `acceptHMRUpdate`，开发热更新保留状态不重置。
- `store/index.js` 创建 pinia 实例并 re-export 5 store，`main.js` 经 `app.use(pinia)` 注册。
