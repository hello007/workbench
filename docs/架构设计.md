## 1. 架构总览

WorkBench 是基于 Wails v2 的桌面应用，采用 Go 后端 + Vue 3 前端 + Wails 桥接层的三段式架构。后端按 `model / service / util / server` 分层，前端按 `views / components / composables / store / utils` 分层，两层经 Wails 自动生成的 `frontend/wailsjs/` 绑定耦合。

### 1.2 Wails 桥接模型

Wails 在 `wails dev` / `wails build` 时解析 Go 端 `App` struct 的导出方法，自动生成 `frontend/wailsjs/go/main/App.js`（运行时绑定）与 `App.d.ts`（类型声明），并根据 `model/` 下被暴露的 struct 生成 `frontend/wailsjs/go/models.ts`。前端 `import { Method } from 'wailsjs/go/main/App'` 后，运行时经 `window['go']['main']['App']['Method']` 调用 Go 后端，返回值序列化为 JSON 传前端。

### 1.3 启动链路

`main.go` 启动流程极简：`NewApp()` 构造空 App → `SettingsService.Load` 读 `data/settings.json`（取 `GpuDisabled` 配 WebView2 GPU）→ `wails.Run` 注册 `OnStartup / OnShutdown / ErrorFormatter / AssetServer.Handler / Bind`。

- `OnStartup`：`NewAppServices` 集中装配全部 service → 清理 diff 临时目录 → 启动 AI 历史清理 goroutine → 注入 update ctx → 检查待应用更新（命中则 `os.Exit(0)` 替换 exe）。
- `OnShutdown`：关闭全部终端会话与 AI 任务句柄。
- `AssetServer.Handler`：`server.PreviewHandler()`，处理 PDF 与 HTML 渲染预览的本地资源请求（embed.FS 未命中时触发）。
- `ErrorFormatter`：`formatAppError`，将后端 error 结构化传前端（见第 5 节）。

## 2. 后端分层

### 2.1 入口与生命周期

| 文件 | 职责 |
|---|---|
| `main.go` | 程序入口；`NewApp` → `SettingsService.Load` → `wails.Run`；注册 `ErrorFormatter: formatAppError`；`//go:embed all:frontend/dist` 嵌入前端产物；`--version` 快速打印版本退出 |
| `app.go` | `App` struct（`ctx` + 内嵌 `*AppServices`）；`NewApp` 零值构造（AppServices 非 nil、字段全 nil，保证 startup 前访问不 panic）；`startup` / `shutdown` 生命周期；`GetAppVersion` |
| `app_services.go` | `AppServices` struct（16 个 service/cache 字段）+ `NewAppServices` 集中装配 |

`App` 内嵌 `*AppServices` 借 Go 字段提升，使 `a.directorySvc` 等直接可达，`app_*.go` 中 138 个委托方法以 `a.xxxSvc.Method()` 形式零 diff 调用各 service（加 `app.go` 的 `GetAppVersion` 共 139 个导出方法）。`AppServices` 必须定义在 `package main`——跨包内嵌时未导出字段不提升，放 service 包会致 `a.directorySvc` 编译失败或被迫全字段大写改写全部委托方法。

`NewAppServices` 仅做纯构造，不执行启动期副作用。以下副作用保留在 `App.startup`，避免构造与生命周期耦合：

- `aiFuncSvc.StartHistoryCleanup()`：定时清理兜底 goroutine
- `updateSvc.SetContext(ctx)`：ctx setter 注入
- `updateSvc.CheckPendingUpdate()`：命中待更新则 `os.Exit(0)`

构造顺序遵循跨依赖：`skillDiscoverySvc` 依赖 `directorySvc`，须在其后构造；`repoConfigSvc` 聚合 `directorySvc` 与 `favoritesSvc`，须在其后构造。

详见 [docs/spec/app-services-assembly.md](spec/app-services-assembly.md)。

### 2.6 预览 handler（server/）

`server/preview.go` 的 `PreviewHandler()` 返回 `http.Handler`，注册为 Wails `AssetServer.Handler`（仅在 embed.FS 未命中时触发）。两条路由：

- `/preview-pdf?path=<绝对路径>`：PDF 内嵌预览，扩展名白名单仅 `.pdf`，`http.ServeFile` 返回二进制（原生支持 Range / Last-Modified，大 PDF 按需读取）。
- `/preview-raw/<绝对路径>`：HTML 渲染预览的静态资源路由（css/js/图片/字体等），白名单扩展 + 绝对路径 + 普通文件校验。

设计要点：扩展名白名单避免被当作通用文件下载器；路径经 `filepath.Clean + Abs` 规范化；本地桌面应用文件路径由用户 UI 选择，不做权限模型判断但限定扩展名降低误用风险。

## 3. 前端架构

### 3.1 框架与路由

Vue 3 Composition API + Vue Router 4（`createWebHashHistory`，适配 Wails 的 `webview` 协议）。路由极简，仅单条：

| 路径 | 组件 |
|---|---|
| `/` | `views/Home.vue`（懒加载） |

`StatsView.vue` 作为子视图组件由 Home 内部按活动面板切换加载，不单独占路由。

### 3.2 Pinia store 拆分

`src/store/` 下 5 个 store，按数据域隔离，`index.js` 统一导出：

| Store | 职责 |
|---|---|
| `directory.js` | 工作目录列表 / 当前选中目录 / 选中节点 |
| `favorites.js` | 收藏夹列表与分组 |
| `workspace.js` | 工作区数据态 |
| `ui.js` | UI 临时态：`activePanel`（directory/ai/stats/toolbox）+ 终端可见性/高度/工作目录 + 弹窗 visible×6 + `appVersion` |
| `settings.js` | 应用设置镜像 |

store 采用 Composition API 风格（`defineStore('name', () => { ... })`），子组件直读直写 store，消除 visible/activePanel prop 透传。

### 3.3 组件层级

| 层 | 内容 |
|---|---|

### 3.4 wailsjs 绑定消费模式

前端组件 `import { Method } from 'wailsjs/go/main/App'` 后直接 `await Method(args)` 调用。绑定文件由 `wails generate module` 生成，整目录 `frontend/wailsjs/` 在 `.gitignore`（自 commit 28ca710），不入库。CI 干净环境须先 `wails generate module` 重建绑定再 `vite build`，否则缺模块构建失败。

前端为纯 JavaScript 项目（非 TypeScript），`App.d.ts` / `models.ts` 仅在 IDE 层提供类型提示，运行时打包不涉及类型导出。完整方法清单见 [API参考.md](API参考.md)。

## 4. 跨层契约

App 方法签名或 `model/` 导出 struct 字段变更时，须手动同步 `frontend/wailsjs/` 三处：

| 变更类型 | 同步点 |
|---|---|
| App 方法签名（增删参数、改类型） | `App.js`（运行时绑定）+ `App.d.ts`（类型声明）+ 前端调用点 |
| model struct 字段（增删字段、改 json tag） | `models.ts` 对应 class 的字段声明 + 构造函数赋值 |
| 具名 string 类型作方法参数/返回值 | `models.ts` 须手动补 `export type X = string` 别名 |

具名 string 类型（`model/commit.go` 的 `MergeMode` / `SubmoduleUpdateMode`）作方法参数时，`wails generate module` 在 `App.d.ts` 保留 `model.MergeMode` 引用，但 `models.ts` 不生成 `export type MergeMode = string` 别名。当前前端纯 JS 不 import `wailsjs/go/models`，运行时打包不触发 `MISSING_EXPORT`，build 通过；若未来前端源码显式 import 并运行时引用缺失导出，则须手动补别名。

`ReadFileBytes` 返回的 `base64` 字段是文件原始字节的 base64，前端还原文本须用 `utils/base64.js` 的 `decodeBase64Utf8`（`Uint8Array` 还原字节 + `TextDecoder('utf-8')`），禁裸 `atob`（Latin-1 逐字节还原致中文双重编码乱码；纯 ASCII 恰好正确故单测须用中文数据）。

文件预览/保存的编码契约：`PreviewFile` 经 `util.DetectTextEncoding` 检测 UTF-8/GBK，转码为 UTF-8 给前端显示并回传 `Encoding` 字段；`SaveFile` 按 `Encoding` 转回原编码写入，不改变原文件编码。

详见 [docs/spec/cross-layer-contracts.md](spec/cross-layer-contracts.md)。

## 5. 错误处理链路

后端 service 返回 `*model.AppError{Code, Message, Err}` → `main.go` 的 `formatAppError`（Wails `ErrorFormatter`）将其序列化为 `{"code":"E_GIT_IN_PROGRESS","message":"..."}` 对象传前端 → 前端 `utils/error.js` 的 `handleError` 读 `error.code` 分流：命中 `WARNING_CODES` 走 `ElMessage.warning`（预期拒绝，用户重试），否则 `ElMessage.error`。普通 `fmt.Errorf` 经 ErrorFormatter 默认返回 `{"message":"..."}`，前端走默认 error 提示。

```mermaid
flowchart LR
  SVC ["service 层<br>返回 AppError"] --> APPM ["App 方法<br>透传 error"]
  APPM --> FMT ["main.go formatAppError<br>ErrorFormatter"]
  FMT -->|"AppError 转 code+message"| FE ["前端 catch"]
  FMT -->|"普通 error 转 message"| FE
  FE --> HE ["utils/error.js handleError"]
  HE -->|"code 命中 WARNING_CODES"| WARN ["ElMessage.warning"]
  HE -->|"无 code 或非 WARNING"| ERR ["ElMessage.error"]
```

错误码常量表维护在 `model/app_error.go`（命名规范 `E_<域>_<动作/状态>`），新增错误码须同步三处：`model/app_error.go` 常量表 + `frontend/src/utils/error.js` 的 `ErrorCode` / `WARNING_CODES` + [docs/spec/logging-and-errors.md](spec/logging-and-errors.md) 错误码表。

当前已定义错误码：

| 常量 | 值 | 域 | 提示级别 |
|---|---|---|---|
| `ErrCodeGitInProgress` | `E_GIT_IN_PROGRESS` | Git | warning |
| `ErrCodeDiffToolNotConfigured` | `E_DIFF_TOOL_NOT_CONFIGURED` | 外部 diff 工具 | warning |
| `ErrCodeDiffToolLaunchFailed` | `E_DIFF_TOOL_LAUNCH_FAILED` | 外部 diff 工具 | error |
| `ErrCodeRepoConfigInvalidJSON` | `E_REPO_CONFIG_INVALID_JSON` | 仓库配置导入导出 | error |
| `ErrCodeRepoConfigUnsupportedVersion` | `E_REPO_CONFIG_UNSUPPORTED_VERSION` | 仓库配置导入导出 | error |

详见 [docs/spec/logging-and-errors.md](spec/logging-and-errors.md)。

## 6. 日志

后端日志用 `log/slog`（标准库）+ lumberjack 轮转，禁 `println`（无级别无落盘，GUI 双击启动时 stdout 不可见）。

- `util.InitLogger(logDir, isDev)` 创建 slog JSONHandler + lumberjack.Writer
- 落盘 `data/logs/app.log`，按 5MB 轮转，保留 5 份，压缩，上限约 25MB，`MaxAge` 30 天
- dev 模式（`version=="dev"`，即 `wails dev`）`io.MultiWriter` 加 stdout，生产构建仅文件
- `NewAppServices` 顶部 `service.SetLogger(slog.Default())` 注入 service 包
- service 包内调 `Logger().Warn(...)` / `Logger().Error(...)`；App 层调 `slog.X`
- 结构化字段必带业务上下文：`slog.Error("clone failed", "repo", name, "err", err)`，禁裸字符串 `slog.Error(err.Error())`

详见 [docs/spec/logging-and-errors.md](spec/logging-and-errors.md)。

## 7. 崩溃恢复（v1.4 PR2）

崩溃恢复持久化 UI 状态快照到 `data/session.json`，崩溃/异常退出后下次启动恢复。MVP 边界：仅恢复 UI 状态，不恢复未提交代码 / 编辑器未保存内容；终端不真实复用进程，仅恢复工作目录。

### 7.1 数据模型

`model.SessionState`：

| 字段 | 类型 | 语义 |
|---|---|---|
| `SelectedDirectoryID` | `string` | 当前工作目录 ID（对齐 `directoryStore.selectedDirectoryId`） |
| `ActivePanel` | `string` | 活动面板：`directory` / `ai` / `stats` / `toolbox` |
| `Terminal` | `*TerminalSnapshot` | 终端面板快照（指针类型，omitempty 对 nil 生效，空快照序列化为 `{}`） |
| `Version` | `string` | 快照格式版本（当前 `1`），便于未来迁移识别旧快照 |
| `SavedAt` | `int64` | 保存时间戳 |

`TerminalSnapshot`：`Visible` / `Height` / `WorkDir`，仅持久化用，不持有进程资源。与 `model.TerminalSession`（运行时会话，含 pty/cmd 句柄与互斥锁）区分。

### 7.2 写入与恢复策略

- **写入**：前端 `composables/useSessionState.js` watch store debounce 调 `SaveSessionState` + `shutdown` 正常退出写最终快照。`SessionService.Save` 写入前补版本号与时间戳，失败 `slog.Error` 记录返回 error，前端静默处理不阻塞 UI。
- **读取**：启动时前端调 `GetSessionState`，`SessionService.Load` 文件不存在或损坏时降级返回空快照（不报错），前端据此走冷启动或恢复流程。损坏场景额外 `slog.Warn` 记录路径与根因。
- **恢复交互**：恢复 `SelectedDirectoryID` / `ActivePanel` / 终端面板可见性/高度/工作目录；文件树展开状态已由 `useTreeState` 持久化到 localStorage（按工作目录隔离），恢复目录 ID 后前端按路径从 localStorage 还原，不纳入快照避免重复。
- **终端恢复**：旧 sessionID 失效，前端用 `WorkDir` 重新 `CreateTerminal` 新建会话，不真实复用旧进程。

`app_session.go` 的 `GetSessionState` / `SaveSessionState` 对 `sessionSvc == nil`（零值构造 / startup 前）做 no-op 防护，不 panic。

跨层契约（`SessionState` 字段对齐前端 Pinia store 实际结构）见 [docs/spec/cross-layer-contracts.md](spec/cross-layer-contracts.md)。

## 9. 测试架构

### 9.1 分层覆盖率门禁

后端 Go 四包 + 主包分层门禁，前端 Vitest v8 coverage 硬失败：

| 包 | 阈值 | 现状基线 | 说明 |
|---|---|---|---|
| model | ≥80% | 100% | 业务核心 |
| server | ≥80% | 91% | 业务核心 |
| service | ≥76% | 76.1% | 含 pty/子进程/网络下载/外部进程等系统调用核心，76% 为实际可达上限 |
| util | ≥40%（排除 `pty_windows.go`） | 42.1% | `pty_windows.go` 按文件名排除 |
| workbench 主包 | 不设门禁 | 26.9% | `app_*.go` 薄包装，service 已测则重复验证价值低 |
| 前端（lines/branches/functions/statements） | ≥70% | 81.67% / 70.26% / 73.75% / 78.84% | `exclude: ['wailsjs/**']` |

CI 门禁脚本 `scripts/coverage-check.sh`：跑 `go test ./... -coverprofile` → 按包解析 → 阈值校验 → 超阈值 `exit 1`。前端 `npm run test:coverage` 低于 thresholds exit 非 0。

详见 [docs/spec/test-coverage-gate.md](spec/test-coverage-gate.md)。

### 9.2 后端集成测试

文件头 `//go:build integration`，默认 `go test ./...` 不编译，CI 显式跑 `go test -tags=integration ./...`。fixture 用 `t.TempDir()` 创建临时仓库 + 本地 bare 远程，显式 `symbolic-ref HEAD refs/heads/master` 规避 `init.defaultBranch` 差异，局部配置 `user.name/email` / `core.autocrlf=false` / `commit.gpgsign=false`，git 不在 PATH 时 skip 不 fail。

### 9.3 E2E 测试（方案 C 混合架构）

| 层 | 载体 | 覆盖范围 |
|---|---|---|
| 前端 E2E | Playwright 驱动 `vite preview` web 版，`window.go` / `window.runtime` 全 mock | UI 编排、跨组件流程、bound method 调用参数、AI 任务事件流状态机 |
| 后端集成测试 | `go test -tags=integration`，真实 git 仓库 fixture | service 链业务逻辑（提交/推送/分支/合并/变基/冲突/submodule 全链） |

关键约定：

- 用例从 `frontend/e2e/fixtures.js` import `{test, expect}`（自动注入 Wails mock，禁直接 import `@playwright/test`）
- mock 默认返回值表唯一来源 `frontend/src/test/wails-mock-defaults.js`（vitest / E2E 共用），禁用例内硬编码重复返回值
- mock 后端每次调用 push `{method, args}` 到 `window.__wailsCalls`，用例经 `getWailsCalls(page, method?)` 断言调用链
- 禁 `waitForTimeout` / 固定 sleep，全程依赖 `expect` 自动重试
- 端口固定 4173 + strictPort（被占直接失败而非漂移）
- CI `retries=2` 吸收偶发抖动 + `forbidOnly` 误提交 `.only` 直接失败
- `frontend/wailsjs/` 不入库，CI 须先 `wails generate module` 再 build

详见 [docs/spec/e2e-testing.md](spec/e2e-testing.md)。

### 9.4 测试辅助

后端测试辅助集中在 `util/testutil/`（v1.4 PR1 抽取），提取重复 fixture 工厂、临时仓库构造、断言助手，与前端 `wails-mock-defaults.js` 单一数据源模式对齐。前端测试 setup 在 `src/test/setup.js`，环境 `jsdom`，Element Plus 组件用 stub。
