# 浏览器模式 - 二期扩展归档

> 归档来源：任务 `.trellis/tasks/09-21-agent` 头脑风暴结论。首版（一期）目标为「桌面全功能对齐到浏览器」，本文记录一期明确不做、但架构已留扩展口子的二期功能，防止后续遗忘。

## 背景

一期交付：同二进制 `--serve`/桌面同开 HTTP 服务，149 个 Wails 绑定方法经通用 RPC 翻译层（`/api/rpc`）+ WebSocket 事件 hub 全部在浏览器可用；token 认证 + 默认绑定 127.0.0.1；终端 PTY over WebSocket。

一期架构已留的口子：前端 transport 适配层（wails/browser 双通道）、WS 连接按会话分发事件、RPC 层与业务 service 解耦。以下二期功能均建立在该基础上。

## 二期功能清单

### 1. Agent 交互式多轮会话（优先级最高）

一期 AI agent 沿用单轮任务式（`claude --print` 跑完归档）。二期升级为网页版 Claude Code 体验：

| 能力 | 说明 | 技术要点 |
|---|---|---|
| 持续会话 | agent 会话保持运行，用户随时查看输入/输出流 | WS 双向通道已有，需会话级多路复用 |
| 中途插话 | 任务运行中追加指令/纠正方向 | 后端持有 stdin 持续写入（`stream-json` input 模式） |
| 权限审批 | agent 请求工具授权时在浏览器弹窗确认 | 拦截 permission 请求事件，映射为前端审批 UI |
| 会话恢复 | 断线/重开浏览器后 `claude resume` 续聊 | 会话 ID 持久化 + resume 参数 |
| 多会话管理 | 同时多个 agent 会话并行，列表切换 | 会话注册表 + 每会话事件流隔离 |

### 2. 连接与会话健壮性

* **断线重连续传**：浏览器断网重连后，终端滚动缓冲与 AI 任务输出从断点续传（一期可能整屏重放，二期做序号增量同步）。
* **多设备同时连接**：一期已支持多连接广播，二期明确多端同时操作的语义（光标/输入冲突策略、按连接隔离的终端会话归属）。
* **移动端适配**：手机临时查看 agent 进度的响应式布局优化。

### 3. 安全增强

* **内置 TLS**：支持用户配置证书（或自签引导），摆脱对外部隧道/反代的强依赖。
* **token 管理细化**：多 token（不同设备不同凭据）、有效期、审计日志（登录/操作记录）。

### 4. 部署形态增强

* **无头服务化**：Windows 服务/开机自启安装器，`--serve` 模式注册为系统服务。
* **文件大流量优化**：浏览器端大文件上传/下载的分块传输与断点续传。
