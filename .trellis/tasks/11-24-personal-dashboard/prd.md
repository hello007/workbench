# 个人数据看板建设（评估结论落地）

## 1. 背景与结论

工作台（WorkBench，Wails + Go + Vue3 单用户桌面应用）已有 10 个侧边栏面板，其中 `dashboard`（仓库状态看板）、`stats`（仓库统计）、`AiTaskHistoryPanel`（AI 任务统计）本身都是洞察视图。真实缺口不是「没有图表」，而是：**现有看板都是仓库维度而非个人使用维度、四路数据分散在四个入口、应用自身使用行为完全没有采集**。

- 总判断：加看板 = **收敛已有数据 + 补一层轻量采集**，不是新建图表系统，不引入 LLM 主链路。
- 架构判断：**明确不迁移 DeepSeek Harness**。DSH 是 Agent 运行时底座，与「把已有结构化数据聚合成可读视图」范畴错配；且处于 developer preview、官方声明会有破坏性变更。若要 Agent 能力，只做旁路集成 PoC。
- 核心 Job：打开工作台 10 秒内知道今天先动哪个仓库、AI 花了多少、哪些事没清。

## 3. 门槛与终止条件

T4 在 P0 上线两周后判定：每周主动打开次数 ≥2，且至少一次因看板改变了当天动作。达成才解锁阶段 3/4；未达成则停止后续投入，退回周报导出脚本或砍掉看板。该门槛用于对抗个人自用场景最高频失败模式「看板变墙纸」。

## 4. 不做的事（Not Now，不建任务）

外部健康/财务/睡眠数据聚合（无数据源、需手动录入）、云同步/多端/移动端、自定义拖拽仪表盘、多租户权限、把审计明细放进浏览器通道、迁移重写到 DeepSeek Harness。

## 5. 贯穿各阶段的工程硬约束

`app_services.go` 两处装配 + `wailsjs` 三处手同步（`App.js` / `App.d.ts` / `models.ts`）；第 11 个面板须自定义快捷键（`Alt+1..9` 已占满），`router/index.js` 不用改；`data/` 写入走 `util.SaveJSON` 原子写 + 损坏留底；日志用 `log/slog`；覆盖率 service ≥76% / 前端 ≥70%；soak 与 goleak 门禁；隐私数据面须加入 `main.go` `RPCHiddenMethods` 并在 `isBrowserChannel()` 隐藏入口。

口径断层必须显式标注：AI 历史 90 天/2000 条、待办已完成 30 天/500 条、审计 5MB×7 档轮转、>5000 commit 采样、ahead/behind 为「相对上次 fetch 的近似值」。

**阶段 2 采集破例（T4 授权）**：阶段 2 为门槛取证破例引入最小采集，范围仅限概览面板进入记录（`data/overview_opens.log`，字段 `ts` / `date` / `source`），不扩到其他面板/指标，不上主看板卡片。判 Go 后 T5 直接复用同一日志器扩展，不得另起一套计数定义。详见 `.trellis/tasks/11-24-dashboard-t4-go-no-go-gate/prd.md` §3.1。
