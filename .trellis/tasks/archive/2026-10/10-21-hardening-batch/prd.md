# 工程加固收口批（goleak 硬门禁 + tilde 走查 + E2E 覆盖）

> 父任务（epic 编排视图）：按序推进三个子任务，本任务自身无代码改动。

## Goal

承接 10-20-ep-caret 依赖治理后的工程加固批次，按风险收益比排序收口三项既有留白。

## 子任务与执行顺序

| 顺序 | 任务 | 目录 | 状态 | 一句话 |
|---|---|---|---|---|
| 1 | goleak CI 观察期收口 | 10-21-goleak-gate | 待启动 | 观察模式切 VerifyTestMain 硬门禁，两步走策略第二步 |
| 2 | tilde 档上游 minor 走查升级 | 10-21-tilde-upgrade | 待启动 | 28 项锁定 minor 对上游差距盘点 + 分批升级走 SOP 必跑面 |
| 3 | E2E 覆盖缺口盘点与补齐 | 10-21-e2e-coverage | 待启动 | 覆盖缺口矩阵 + 高价值链路补齐（路线图留白项） |

## 执行约定

- 子任务各自走完整 trellis 流程（brainstorm → prd → jsonl → start → implement → check → finish），独立提交与归档
- 前一子任务归档后再 start 下一子任务（顺序推进，避免并行改动面交叉）
- 子任务间依赖：任务 1 与 2 无耦合可独立验证；任务 3 的 E2E 增补应在任务 2 升级后进行（避免用例断言基于旧版本行为写入后升级返工）
- 父任务在三个子任务全部归档后收口归档，journal 记录批次总结

## Out of Scope

- 批次外新需求（素材域功能、AI 域扩展等）
- caret 档治理翻案（10-20-ep-caret ADR 已定策）
