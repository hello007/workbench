# E2E 焦点与光标断言鉴别力范式

## 1. 背景

11-14-e2e 为「临时待办全屏编辑」与「提示词编辑弹窗」补了 7 条用例，过程中得到两条可复用结论：

1. **新建/首次赋值的 textarea，在 Chromium 中 focus 后光标默认落在末尾**（赋值即把 selection 置为 `value.length`），因此打开后直接断言 `selectionStart === value.length` 无法区分 `focus()` 与 `setSelectionRange(len, len)`——断言恒真，无鉴别力。有效鉴别需「置 0 → 经保留草稿的关闭路径复用节点 → 重开 → 再断言」，并显式钉住 DOM 复用前提。
2. **每次打开都重新赋值输入框的场景**（如提示词编辑弹窗：`@closed` 复位草稿 → 重开重新赋 `draftTitle`）在用户可见层无法区分两种实现，属**可接受残余风险**，但必须在文档与用例注释中写明前提与边界，避免后续评审误认为已覆盖。

上述两条目前只散落在两份 spec 的注释里，缺少统一范式文档；同时其余「打开即聚焦」入口是否存在同类覆盖缺口未经系统排查。
